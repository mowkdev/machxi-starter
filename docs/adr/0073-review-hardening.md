## Context

The review of 2026-09-13 read the repository at `28fa5d6` and found no defect that is exploitable in the reference deployment. What it found is a set of accepted single-instance assumptions and drifts that are each an hour or a step to close, and that a fork would otherwise inherit: the argon2 pool budgeted per address only, a limiter key that becomes one bucket under a wrong proxy hop, sessions that grow until an operator remembers a CLI, bundle ceilings a few percent above measurement with nothing bounding a raise, four exact pins nobody can explain, `updated_at` and the proven-address invariant kept only by the code that remembers them, and a gate that does not run the two checks that were red. Several of these are decisions the records already reserved a place for — [ADR-0020](0020-security-baseline.md) §Residual risks names the per-principal budget, the ADR index's planned list names the prune's scheduler — and none of them needs a new mechanism. This record makes the decisions in one place so that D20 is a build and not a debate, and each is a delta small enough for a fork to drop on its own.

## Decision

### 1. A per-principal budget on the routes that spend a hash under a session

A fifth limiter category beside ADR-0020's four: **keyed on `ctx.principal.id`** (the impersonation limiter's shape), mounted on `POST /user/profile/change-password`, `DELETE /user/profile`, `DELETE /user/profile/identities/:provider`, `POST /admin/staff/:id/password` and `POST /admin/users/:id/password`, with `RATE_LIMIT_PRINCIPAL_HASH_MAX` (default `10`) per `RATE_LIMIT_PRINCIPAL_HASH_WINDOW` (default `15m`). It closes two things at once: the pool the review names (a few authenticated clients can no longer make the hash limiter shed login for everyone) and the oracle on the administrative reset (an actor guessing their own password is bounded by their own budget, not by the global one). The `429` carries the standard shape and the standard headers; the limiter shares the store of ADR-0066 §4.

**Amended 2026-09-17 (`D20.4`)**, by the step that builds this section, against what the routers turned out to hold — this step's `security-reviewer`. **The rule is the criterion, not the list**, and the list above was short by two the day it was written: **every authenticated route that verifies a password through the hash limiter carries this budget.** The three that were missing are on it:

- **`POST /user/profile/change-email`** ([ADR-0071](0071-mail-flows.md) §6). Its only limiter is keyed on an address the caller typed and **refunds every refusal** — deliberately, since what that one rations is a mailbox — so a wrong `currentPassword` bought an argon2 operation from login's pool and spent no budget at all, from any self-registered account. It is the liveness hole this section exists to close, left open on the one route nobody re-read.
- **`POST /admin/staff/:id/email` and `POST /admin/users/:id/email`** ([ADR-0071](0071-mail-flows.md) §7). Both verify the **actor's own** password before the subject is read and answer `403` when it fails, which is the oracle this section describes for `:id/password`, one hash per guess — and the credential being guessed there is a super admin's, the worst one to leave unbounded. `authorize("super_admin")` narrows who may knock; it does not bound how often.

Seven mounts today. The roster is a fact about the routes rather than about this record ([ADR-0050](0050-adr-lifecycle-and-verification.md) §Altitude): `docs/specs/` states what a client observes and the integration tier proves it, and a route added later that verifies a password is on the list by the criterion above whether or not anybody amends this paragraph again.

### 2. A limiter key never degrades to one shared bucket

When the context middleware has no validated address — `req.ip` was not an address under a mis-stated `TRUST_PROXY` — the limiter keys on **`req.socket.remoteAddress`** and one `warn` per process names the configuration, rather than keying every caller on `""`. The fallback address is still not written to `sessions.ip`; only the key uses it.

**Amended 2026-09-17 (`D20.4`)**, by the step that builds this section: the warning is emitted by the **limiter's key generator**, not by the context middleware. Two reasons, and the second is the one that settles it. The degradation is taken in the key, so the sentence and the behaviour cannot drift apart — only the key generator knows that it fell back. And `createContextMiddleware` holds no configuration to name: giving it one so that it could mention `TRUST_PROXY` is a larger change than putting the line where the fallback happens. The behaviour this section decides is unchanged in every observable way.

### 3. Sessions: a cap per principal, and a prune the deployment runs

Login and the federated exchange revoke the principal's oldest live sessions beyond **`AUTH_MAX_SESSIONS_PER_PRINCIPAL`** (default `10`, `0` meaning uncapped) inside the mint's transaction, with `revoked_reason = 'session_cap'`. Impersonated sessions count against the impersonated user and are never the ones revoked (they end on their own clock, ADR-0057). The reference deployment gains a **`prune` service**: the API image with the `db:sessions:prune` entry as its command, `restart: unless-stopped` with a sleep-loop interval of `PRUNE_INTERVAL` (default `24h`), documented in `docs/deploy.md` beside `migrate`. An in-process scheduler stays a later row's decision (ADR-0066's seam shape); this record only guarantees that a production database stops growing by default.

### 4. Server timeouts, and the runtime floor

`server.ts` sets `requestTimeout`, `headersTimeout` and `keepAliveTimeout` from `HTTP_REQUEST_TIMEOUT` (default `30s`), `HTTP_HEADERS_TIMEOUT` (default `10s`) and `HTTP_KEEP_ALIVE_TIMEOUT` (default `65s`, above a typical proxy's `60s`), beside the drain deadline. The runtime floor moves to **Node 24** in `.nvmrc`, `engines`, both workflows and the three Dockerfiles together, and the package manager to **pnpm 12**; the API image's `pnpm deploy` flag is re-verified on that version.

**Amended 2026-09-17 (`D20.3`)**, by the step that builds the floor half of this section, against what the two versions turned out to bring with them. ([ADR-0002](0002-monorepo-layout-and-tooling.md) §Toolchain versions is where `engines.node: ">=22"`, the root `.nvmrc` and `pnpm@10.x` were decided, so it **moves to `superseded by` at this head too**, with the delta on its `Supersedes:` line above: the `D20.2` reading does not stretch this far, because there the tool renamed an option 0002 had named and here the decision itself is reversed. Frozen forbids amending 0002 in place; superseding it is the machinery that exists for exactly this.)

- **The floor is a patch line, not a major.** `>=24` would repeat the mistake it replaces: the tree's strictest constraint today is `jsdom`'s `^22.22.2 || ^24.15.0 || >=26.0.0`, and a contributor on 24.0–24.14 would satisfy the repository and not its test DOM. `engines.node` is therefore **`>=24.15.0`**, the real floor read off the dependency tree, and it moves when a dependency raises it. `.nvmrc` stays the bare major, which is what a version manager resolves to the newest 24.
- **pnpm 12 no longer reads the `pnpm` field of `package.json`.** Its settings live in `pnpm-workspace.yaml` beside the `catalog:`, and `onlyBuiltDependencies` — a list of who may run an install script — is now **`allowBuilds`, one `true` or `false` per package**, with an install that *refuses* rather than warns when a package it has no answer for wants to run one. Each answer is in that file with its reason.
- **The supply-chain cooldown is a check on the choice, not on the install.** pnpm 12 defaults `minimumReleaseAge` to 24 hours and, new in 12, re-verifies it against every entry of the lockfile on every install — so a lockfile committed the day a dependency moved refuses to install anywhere, image builds and CI included, until the clock catches up. The decision is **`trustLockfile: true`**: the cooldown stays on where the version is chosen (`pnpm add`, `pnpm update`, a Renovate branch), and a lockfile that is already through a pull request and the gate installs. `--no-trust-lockfile` re-checks it on demand. The cooldown itself is written down (`minimumReleaseAge: 1440`) rather than inherited from a default, because a decision this section leans on must not be a number the tool is free to change.
- **`@types/node` stays on the 22 surface, and that is a deferral rather than an oversight.** The catalog's `^22.20.3` is a major behind the floor this section moves. It is taken in `D21` with the other majors, one pull request each (ADR-0059 §3), and until then the effect is conservative in the right direction: code cannot reach for a Node 24-only API without the types refusing it. It is also the first thing the cooldown above charged for — a re-resolution on the day after a dependency sweep is refused until the picks mature, which is exactly the protection working and exactly why a major does not ride in on a floor move.
- **`.npmrc` is gone with the settings.** pnpm 12 does not read it, and the file held one line — `auto-install-peers = true`, which `renovate.json`'s pinning register leans on as the reason `@vitest/coverage-v8` is pinned with `vitest`. It is now **`autoInstallPeers: true`** in `pnpm-workspace.yaml`, where the tool reads it; a file left behind stating a setting nothing reads is the drift this deliverable exists to close.
- **The lockfile now locks the package manager too.** pnpm 12 writes a first YAML document into `pnpm-lock.yaml` pinning itself and its per-platform binaries; it is the tool's output and is committed as such.
- **`pnpm deploy --legacy` is dropped.** The flag existed because pnpm 10 refused to deploy a workspace that does not inject its internal packages; pnpm 12 does not refuse, and the image's two constraints — one `pino`, `argon2`'s prebuilt binary — hold without it. The reason is in `apps/api/Dockerfile` beside the command.
- **Corepack is the way in, and now it is the only way in.** pnpm 12 ships as a native binary, and a pnpm 10 or 11 already on the path cannot launch it through the `packageManager` field — it writes a shim to a file the new layout does not have. `corepack enable` was already the documented setup step ([`README.md`](../../README.md) §Requirements) and the three Dockerfiles' first instruction; what changes is that an older standalone pnpm is no longer a working substitute.

### 5. Bundle ceilings are bounded by headroom over a committed baseline

`size-budget.json` keeps its shape (ADR-0062 §4) and gains a rule `scripts/size.mjs` enforces: **every ceiling is at most 15% over its baseline**, and every baseline is re-measured in the diff that raises a ceiling. A raise is therefore always a diff that shows both numbers, and a baseline cannot go stale without the script saying so. Below the route split, the **`lv` catalogue is loaded through the i18next backend already in place** and **`@repo/grid` is a dynamic import behind the list pages**, so the entry ceiling falls rather than the js ceiling rising.

### 6. The gate runs everything that can go red

`pnpm check` and the gate's first link (`pnpm lint`) gain **`pnpm test:scripts`** and **`pnpm docs:check`**, both seconds. The shared Vitest configs report **`coverage` as a `text-summary`** with no threshold; a floor per package is a later decision taken on a number rather than on hope. Postman stays nightly beside the browser tier, where the stack exists.

**Amended 2026-09-18 (`D20.7`).** A link that runs is not yet a link that checks. `check-types` declares `dist-types/**` as its cached output and `tsc -b` keeps its incremental state inside it, so a restored buildinfo can tell the compiler there is nothing to do and the task exits `0` — the gate replayed a green `check-types` over seven errors in `apps/admin` until `D20.7`'s split invalidated the cache from a dependency. This section therefore has a second half: **a cached task's restored outputs must not be able to decide the task's own result.** The compiler's memory leaves the cached output at `D20.12`; what ADR-0026 says about caching, as carried here, is unchanged — the emitted declarations were the wrong place to keep it, not the wrong thing to cache.

### 7. Pinning, catalogs, digests, images

`renovate.json` and the manifests follow one stated rule: **exact for the runtime framework and the compiler (`express`, `typescript`), caret for everything else** — so `tsdown` is unpinned. The versions ten or more workspaces declare move into a **`catalog:`** in `pnpm-workspace.yaml`. GitHub Actions are **pinned by digest** (`helpers:pinGitHubActionDigests`) and the four base images gain a named Renovate rule. Runtime-reachable advisories are closed by taking `nodemailer` to its current major and `qs` to `6.16`; a `pnpm audit --prod` that reports nothing reachable is the check.

**Amended 2026-09-17 (`D20.2`)**, by the step that builds this section, against what the tree turned out to hold:

- **The caret rule has one exception and one more pin than it named.** `jsdom` is held **below 30.1.0**: that release rewrote the DOM-tree, CSS and HTML-collection internals, and under it a Radix dropdown opened in a second app render of the same test file never mounts its menu — fourteen customer tests, each green on 30.0.1 and green on 30.1.0 run alone. An exact version in the manifests is what actually holds it (`allowedVersions` only constrains Renovate's own pull requests), so the hold is an exact pin with its reproduction in `renovate.json`'s rule, and it is lifted by taking a later jsdom and running that suite whole. `@vitest/coverage-v8` is exact for a reason the package states itself: its peer on `vitest` is an exact version rather than a range, so the pair moves in one pull request or `autoInstallPeers` answers the unsatisfiable peer with a second copy of vitest. **Every exact pin is named in `renovate.json`'s pinning rule with its reason** — that register, not this list, is the thing a reader checks.
- **The bundler's option names moved with it.** `tsdown` unpinned lands on 0.23, where [ADR-0002](0002-monorepo-layout-and-tooling.md)'s `noExternal` / `external` are `deps.alwaysBundle` / `deps.neverBundle`; 0002 is inherited and frozen, so the rename is recorded here rather than edited there, and its decisions are untouched. One more option is load-bearing: 0.23 defaults `platform: "node"` to a fixed `.mjs` extension, and **`fixedExtension: false` keeps `dist/main.js` and `dist/migrate.js`** — names `apps/api/Dockerfile`, `docker/prod/compose.yaml`, the `start` script and [`docs/deploy.md`](../deploy.md) all say out loud.

### 8. Two invariants move into the database

`timestamps()` gains **`.$onUpdate(() => new Date())`** on `updated_at`, so a repository that forgets the column can no longer ship a stale one; repositories that set it explicitly keep working. A migration adds **`CHECK (status <> 'active' OR email_verified_at IS NOT NULL)`** to `users`, preceded by a backfill assertion that fails the migration if a row violates it — the invariant ADR-0071 §3 and ADR-0072 §1 lean on becomes a database error rather than a review finding.

### 9. A Content-Security-Policy on the SPA images

Both `nginx.conf` files send `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self' <API origin>; frame-ancestors 'none'; base-uri 'self'; form-action 'self'`. `'unsafe-inline'` on styles is Tailwind's price and is stated; scripts are the injection the policy exists to stop. The API origin is a build argument beside `VITE_API_URL`, since nginx cannot read Vite's.

### 10. The composition root is wired per module

`core/container.ts` becomes ordering only: `createRateLimiters(config, store)` returns the named set, and each module exports one `wire<Module>(deps)` returning its repositories, services and controllers. ADR-0009's layering is unchanged; what moves is where a fork's merge conflict lands.

## Consequences

- Six new environment keys (`RATE_LIMIT_PRINCIPAL_HASH_MAX`, `RATE_LIMIT_PRINCIPAL_HASH_WINDOW`, `AUTH_MAX_SESSIONS_PER_PRINCIPAL`, `HTTP_REQUEST_TIMEOUT`, `HTTP_HEADERS_TIMEOUT`, `HTTP_KEEP_ALIVE_TIMEOUT`) enter ADR-0004's schema, `.env.example`, `apps/api/.env.test`, `docker/prod/.env.example` and `docs/deploy.md`; `PRUNE_INTERVAL` enters the compose file and the deploy guide only.
- A person with more than ten devices signs out of the oldest at the eleventh login; the number is a default, and the sentence lands in `auth-sessions.md`.
- The CSP breaks the first inline `<script>` a build step ever emits, loudly, which is the point; nonces are the answer then.
- The catalog moves version truth to one file; a workspace that needs to diverge names the version directly, which is visible.
- The container split touches every module once; it is behaviour-preserving and the integration tier is the proof.
- What this record does not decide, by design: the key ring (SEC-01), row-level security (SEC-07), the in-process scheduler and an outbox (DB-02, API-05), the shared composition's second wave (FE-01) and the record consolidation (PRO-02) — each is a planned ledger row of its own.

## Alternatives considered

- **One record per decision** — ten short records; cleaner topic rows, ten more links in the chains PRO-02 already names. One record with ten deltas is the D19 shape and reads as one wave.
- **A hard cap that refuses the eleventh login** — punishes the person for a stolen device; revoking the oldest is what every consumer platform does.
- **`CREATE INDEX CONCURRENTLY` lane and RLS here** — both are migration-runner decisions with their own preconditions; they belong to the RLS row.
- **A coverage threshold now** — a number chosen before it is measured is a number that gets edited on the first red run.
- **Refusing the request when the limiter has no address** — safer in theory, and it turns one mis-set variable into a total outage; a warning and the socket address keep the service up while saying what is wrong.
