## Context

The review of 2026-09-21 read the repository at `630d2b6`, verified the fate of every finding D20 took, and found nothing exploitable. What it found is a set of gaps of one shape: decisions [ADR-0073](0073-review-hardening.md) made whose mechanism reaches less far than its sentence. The gate's first link runs the inner loop's checks but one; a version hold binds the manifests and not the peer the installer resolves on its own; a supply-chain cooldown is stated for one tool and not the other; the digest the ship regenerates was regenerated and not extended, so a session loading `docs/rules/` sees none of D20's decisions; the session cap counts sessions the customer did not open; a "spend every link" rule was copied by hand and its fourth twin was left short; the policy header is tested in the file it lives in and not on the page it governs; a client directive is kept for a consumer nobody can name; the line ceiling guards the trees D20 split and not the one it did not. None needs a new mechanism, and each is a delta small enough for a fork to drop on its own. This record makes them in one place so that D28 is a build and not a debate.

## Decision

### 1. The first link carries every check that can go red

`i18n:check` joins `lint`'s `dependsOn` in `turbo.json`, beside `test:scripts` and `docs:check`: the task is pure and cached, so it costs the gate seconds and a terminal nothing it did not already pay. [ADR-0046](0046-interface-localization.md) §9 promised that forgetting a key is red in `pnpm check`; the review's `CI-08` shows the promise held for a terminal and not for a pull request. `pnpm audit --prod` — the check ADR-0073 §7 named and nothing ran (`CI-09`) — runs **nightly in the e2e workflow, reported and never gating**, the standing coverage has: a fresh advisory is a fact about the world and not about the diff. A hygiene case asserts that **the first link's dependencies name every root and app check the repository defines**, so the next check that can go red joins by predicate rather than by memory. Delta on ADR-0073 §6, and so on [ADR-0026](0026-task-graph-caching-and-serialisation.md) as carried.

### 2. One fact per hold, one cooldown for both tools

A dependency held below a version is held by a **`pnpm-workspace.yaml` `overrides` entry**. The exact pins ADR-0073 §7 chose and `renovate.json`'s `allowedVersions` rule constrain the manifests' own declarations and Renovate's pull requests — and nothing else: `autoInstallPeers` answers a peer range no manifest mentions with whatever the registry has, which is how the held `jsdom` release arrived as a second copy in the lockfile for the workspaces that never declared it (`STK-08`), exactly the case the pinning register's own note predicts. An override binds the resolution, so the hold is one fact rather than a pin per workspace and a hope; the reproduction stays in the register, which remains the thing a reader checks. **`minimumReleaseAge` is stated once for pnpm and once for Renovate with the same value**, so a version pnpm refuses is one Renovate does not propose (`STK-09`). The procedure for taking a security fix younger than the cooldown is written beside the pnpm setting: the CLI override for that one install, in the branch that takes it, with the reason in the pull request. Delta on ADR-0073 §7 and on [ADR-0059](0059-ci-containers-and-deployment.md) §3 as carried.

### 3. Every accepted record is the primary citation of at least one digest line

`scripts/rules-digest.mjs` carries **one rule line per decision a record makes that a session must obey**, and the generator **refuses to run when an accepted record is cited by no line as its primary**. `rules:digest` writing nothing can mean "nothing changed" or "nobody extended it", and D20 shipped on the second reading with the first's done-when: ADR-0073's decisions reached a session only as a suffix on lines older than it (`PRO-08`). The check makes the derived document derived in both directions — a supersession flips a status and the regeneration follows it or fails, which is [ADR-0065](0065-starter-lifecycle.md)'s rule, and now an acceptance adds a record and the regeneration carries it or fails. D28 writes ADR-0073's lines and this record's own. Delta on ADR-0065 §5's digest bullet, as carried by [ADR-0068](0068-behaviour-specs-and-plan-notes.md).

### 4. The cap counts the principal's own sessions

An impersonated session — a row with `impersonated_by_staff_id` — **neither counts toward `AUTH_MAX_SESSIONS_PER_PRINCIPAL` nor is evicted by it**; it ends by its own TTL and by [ADR-0057](0057-impersonation-sessions.md)'s rules. ADR-0073 §3 counted it and exempted it from eviction, and `SEC-09` shows where that lands: the mint budget for impersonation is the staff member's, so the count a customer's cap is measured against is one somebody else fills, and the eviction falls on the customer's own devices. The cap is a bound on what a person holds, and a session they did not open is not theirs to hold. Delta on ADR-0073 §3, and so on [ADR-0018](0018-authentication-sessions-and-tokens.md) as carried.

### 5. A credential event spends every outstanding link

One **`supersedeAll(ctx, principal, tx)` in `core/tokens`** replaces the per-purpose loops the services carried, and every credential event calls it: the administrative reset on a user, the staff reset, a password change, and an account deletion. [ADR-0071](0071-mail-flows.md) §7 already decided the rule for an address change — every link, iterated over the purpose enum rather than listed — and §6 decided a narrower one for a password change; copied by hand, the loop reached the staff paths and the address change, while the administrative reset on a user spent two purposes by name under a comment arguing the opposite (`API-09`) and deletion spent none (`DB-11`). A function with one name is what makes the rule checkable: a unit case asserts it covers every purpose, and a purpose that should survive a credential event says so where it is declared, the safe direction §7 chose. Delta on ADR-0071 §6 and §7 as carried; additive on [ADR-0028](0028-account-deletion.md), which never spoke of tokens.

### 6. The policy is proved on the page it governs

The `size` link's build is followed by a check that **neither built `index.html` carries an inline script, an inline style element or an event-handler attribute**. The `nginx.conf` files ship only in the images and the browser tier runs against dev servers with no policy (`SEC-10`), so a plugin that begins emitting an inline bootstrap breaks the app only in production, which is the one place the policy exists. The check is stricter than the policy on styles — `'unsafe-inline'` is Tailwind's stated price, and the check keeps the built page from spending it — so the price can be withdrawn later without first discovering who else was paying. Delta on ADR-0073 §9.

### 7. No client directive in `@repo/ui`

The `"use client"` rule and the directive **leave the compositions and the skills**. [ADR-0047](0047-ui-package-scope.md) §What-code required the directive for a Next consumer that `apps/web` was and no app is — `D14.1` deleted the placeholder, and `D20.1` removed the sentence naming it while leaving the rule (`FE-12`). A rule whose only rationale is a consumer nobody can name is one a reader must guess at, and a directive nothing consumes is a claim no suite can refute. A Next consumer, when D16 adds one, reintroduces the boundary by its own record, where it can be tested against the consumer that needs it. Delta on ADR-0047 §What-code (the stateful-compositions bullet) and its §Consequences' definition-of-done line.

**Amended 2026-09-22 (D28.11).** [ADR-0048](0048-app-shell-and-record-surfaces.md) restated 0047's rule as its own — §1's "Stateful compositions carry `"use client"`", the directive annotated on three files of its tree, and §Consequences' "`"use client"` included" — so after `D28.9` it narrated a withdrawn rule to anyone who read it rather than 0047. On the operator's decision the delta names it too: those three statements are withdrawn with 0047's, and every other decision of 0048 stands.

### 8. The line ceiling covers `core`

`apps/api/src/core` **joins the roots the thousand-line ceiling guards**. The ceiling was set on the trees D20 split, and the largest file left outside it sits in the one tree it did not name (`API-08`); a rule that guards where it last cut and not where the next cut will be is the quiet ratchet ADR-0073 §5 refuses for bundles. Delta on ADR-0073 §10.

### 9. A unit suite's hash covers its workspace dependencies

**Amended 2026-09-22 (D28.11)** — added on the operator's decision of 2026-09-22, from what `D28.10` found. **`test:unit` depends on turbo's `transit` node**, a task no workspace defines as a script and that depends on `^transit`: it runs nothing and waits on nothing, and each package's `transit` hashes that package's files and its own dependencies' `transit`, so an app's unit hash covers the source of every workspace package it runs. [ADR-0026](0026-task-graph-caching-and-serialisation.md)'s rule — a result may be cached if and only if it is a pure function of the repository contents — was stated for the whole repository and applied per package: `test:unit` declared `dependsOn: []`, so `admin#test:unit` hashed admin's 301 files and nothing else, and a change in `@repo/vitest-config` or `@repo/grid`, source-only packages whose code the admin suite executes, replayed the previous green from `pnpm check` and `pnpm test:unit`. The gate's `test` is uncached and was never fooled; the inner loop was. `^test:unit` would close the gap too, by running every package's suite before its consumers' and serialising the fast loop for nothing. A hygiene case refuses a `test:unit` with no `^` edge, and a transit a workspace would run. Delta on ADR-0026 §The task table's `test:unit` row, as carried by [ADR-0052](0052-grid-and-admin-followups.md) and [ADR-0073](0073-review-hardening.md); nothing else in it.

## Consequences

- D28's steps are the mechanisms above, one each: the dependency and its hygiene case, with the nightly audit step; the override and the paired cooldowns, with the procedure beside them; the generator's lines and its refusal; the cap's count, and the sentence in `auth-sessions.md` that says whose sessions it counts; `supersedeAll` with its unit case, called from every credential event; the built-page check beside `size`; the directive's removal from the compositions and the two skills; the roots list. **Amended 2026-09-22 (D28.11):** and, at `D28.11`, 0048's Status line for §7's widening, and the `transit` edge with its hygiene case for §9.
- **The coverage-on-the-gate question is measured, not decided here.** `FE-09` is D28's spike step: `coverage.enabled` off on the gate and the source-only packages pre-bundled, in a worktree, the two numbers written in the notes. If the measurement changes the default run, this record is amended there, labelled — the window is open while D28 is in progress ([the ledger](../plan/README.md#the-window)).

  **Amended 2026-09-22 (D28.10).** Measured, and it does change the default run. The admin tier, twice each way on one idle machine: **127.1s and 125.4s with v8 coverage on every run, 92.3s and 92.7s with it off** — about 27% of the gate's slowest link. So **the jsdom suites collect coverage only when asked** — `packages/config-vitest/react.ts` sets `coverage.enabled: false` with the provider and the `text-summary` reporter still written out, and `pnpm test:unit --filter <workspace> -- --coverage` prints the summary it always printed. The node suites keep it on every run: they were not the bill, and nothing was measured there. A delta on ADR-0073 §6's "the shared Vitest configs report coverage", nothing else in it; no threshold, as before. **Pre-bundling is not a config change.** Vitest's `deps.optimizer.client` over the seven source-only packages broke the suite: with the seven alone, 38 of 60 files failed on a second copy of the router's and React's contexts inside the bundle, and one ran past ten minutes on timeouts before the run was stopped; with React, the router, Query, Table, i18next, react-hook-form and Testing Library bundled beside them and the JSX transform set, 44 of 537 tests still failed on the `@repo/ui` and Radix instances outside the bundle, in 150.5s. `server.deps.inline` changes nothing here — linked workspace packages are already transformed rather than externalised. Removing the re-transformation means the harness and the suites living in the packages, which is D22's row, and the numbers are its input there.
- D21's majors land on the extended gate; a `jsdom` major lifts the override or renews it with its reproduction.
- D26 restates this record's deltas with ADR-0073's, so the chains it consolidates read as one wave rather than two.
- What this record does not decide, by design: the operations rows (D24), the composition's second wave (D22), the record consolidation (D26) and the compiler's memory (D27) keep their rows; the review routes its remaining findings to them by name.

## Alternatives considered

- **No record — labelled deltas only**, the review's own suggestion for the wave. Rejected because the first link's dependencies, the cooldown and what the cap counts are decisions ADR-0073 did not make, and every parent here has shipped: a change to a frozen record is a supersession or a divergence, and the window rule leaves no third thing.
- **Keeping the client directive for a future consumer.** It costs nothing to keep and nothing tests it, which is the problem: a rule kept for a consumer no record names is exactly the claim [ADR-0050](0050-adr-lifecycle-and-verification.md)'s altitude keeps out of a record. The consumer's record is the right place, and it does not exist yet.
- **A coverage threshold** — still not; a number chosen before it is measured is a number edited on the first red run. The spike measures the cost of collecting it at all.
- **Renovate's cooldown alone, with pnpm's off.** Rejected: pnpm's is the one that protects a `pnpm add` from a terminal, which is where a day-zero version actually enters.
- **Bounding the impersonated sessions in the same cap** — a second number for the staff side. Rejected: the mint already has a budget per staff member (ADR-0057 §1), and a second cap on the customer's row would still be a count somebody else fills.
