# D8 — App shell and record surfaces

- Status: **planned** — opens when the previous deliverable ships (D7 has: 2026-08-22); per the ledger, opening is a decision, not a formality. Its ADRs — [0047](../adr/0047-ui-package-scope.md), superseding frozen [0031](../adr/0031-ui-design-system.md), and [0048](../adr/0048-app-shell-and-record-surfaces.md) — were **written ahead on 2026-08-22** and are `proposed` (writing is not opening, the D4 precedent); both are accepted at the head of `D8.1` (§Gate below)
- Steps: `D8.1` – `D8.7`
- Ledger: [`docs/plan/README.md`](README.md)

Scope: the two compositions every screen in both SPAs is built from — **the application shell** and **the record surface** — designed as generic, slotted components in `@repo/ui`, with `apps/admin` adopting them as the first consumer. Nothing behavioural moves in this deliverable: the grid, the API client, the resource config and the form machinery stay exactly where they are (that is [D9](0009-platform-extraction.md)). What moves is presentation, and what changes is that two hardcoded layouts become two designed ones.

**This is design work, not a move**, and that is why it comes before the extraction. `apps/admin` is a working consumer with a full test tier and a browser walk; generalising the shell and the surfaces **against it, in place** is the cheapest verification available. D9 afterwards is then a mechanical relocation whose "no behaviour change" claim is checkable by test totals.

## Why now rather than with the customer app

The scope document these two deliverables were split out of made the opposite argument — _"an extraction with one consumer is speculation with extra folders; the second app is the forcing function."_ That argument stands in general and is answered specifically here: **the second consumer's requirements are already known** (a collapsing nav drawer, header chrome placed differently from the admin panel's, and create/edit surfaces in three shells), and both compositions are ones the customer app cannot be written without. The risk the old argument names is speculative generality, and the plan carries a rule against it rather than a hope:

> **Every slot and every variant must answer a need this repository can name today** — a screen in `apps/admin`, a stated requirement of the customer app ([D11](0011-customer-app.md)), or an invariant a frozen ADR already imposes. A slot added because it "might be useful" is a review failure.

## What is wrong with today's two layouts

Both gaps are real and were read out of the code rather than assumed.

**The record surface scrolls the wrong thing.** `apps/admin/src/shared/form/app-form-surface.tsx` puts `overflow-y-auto` on the drawer's entire `SheetContent`, so the title scrolls away with the fields; there is no fixed footer region at all (the actions are a `FOOTER` class string inside the scrolling body); the modal has exactly one width; and the footer's contents are fixed — `AppFormActions` and nothing else. A form long enough to scroll therefore loses both its title and its Save button, which is the case the operator most needs them.

**The shell has no slots.** `apps/admin/src/widgets/dashboard-layout/index.tsx` hardcodes its header as `SidebarTrigger + Separator + <h1>{title}</h1>`. There is nowhere to put an action, a breadcrumb or a status control, which is why theme, locale and logout ended up in the _sidebar footer_ — not because that is where they belong, but because it was the only region that took children. A second app that wants them in the header would have to fork the layout.

## The shell

A composition over `@repo/ui`'s `sidebar-07` primitives, which **knows nothing about routing or authorization**: navigation arrives as JSX, so the `can()` join (ADR-0042) and the typed route links stay in the app that owns them.

- **`brand`**, **`nav`**, **`sidebarFooter`** — the drawer's three regions. `collapsible="icon"` behaviour and the mobile `Sheet` swap are the primitive's, unchanged.
- **`headerStart`** / **`headerEnd`** — the fix for the stranded chrome. The trigger stays the shell's; everything beside it is the app's, on either side.
- **`breadcrumbs`** — `packages/ui/src/components/breadcrumb.tsx` has been in the package since D3.1 and has never been rendered. The shell is where it belongs.
- **The page header** — a title-and-actions row for a page, replacing the ad-hoc `CardHeader` / `CardAction` usage. The grid toolbar keeps its own actions (ADR-0038 put Create there deliberately at D4.3); this serves the pages that are not grids.
- **`banner`** — a full-width region above the header, and a standard shell region rather than a speculative one: every app of this shape eventually needs somewhere to say something about the whole session. It is **dumb by construction** — it renders what it is handed and reserves no space when handed nothing. The shell must not learn _why_ a banner is showing, because a shell that read the principal would drag the session store and `@repo/contracts`'s principal type into `@repo/ui`, which ADR-0031's dependency rule and [ADR-0023](../adr/0023-shared-contracts-package.md) both exist to prevent.

  It comes with a generic **`Banner`** component beside it — variants, a message, an action slot, and a **`dismissible`** flag, because its first real consumer needs `dismissible={false}`. `@repo/ui` has no `alert` primitive today, so whether this is built on shadcn's or hand-written is the ADR's call.

  **The named consumers, in order of certainty**: [D12](0012-impersonation.md)'s impersonation banner, which reads `principal.impersonatedBy` and renders into this slot — the field on the principal and the banner itself are D12's to add, not this deliverable's; then offline, maintenance and read-only notices. In `apps/admin` today the honest consumer is the dev-only pseudo-locale notice: `VITE_I18N_PSEUDO` (D7) is on and nothing says so on screen, which is a real if small need and makes the slot _exercised_ rather than merely offered. A slot with no consumer at all is the defect this repository recorded twice about the `page` edit surface, and the deliverable should not add a third.

- **The page container**, carrying [ADR-0037](../adr/0037-grid-viewport-layout.md)'s height contract unchanged — `min-w-0` always, `min-h-0` and `h-svh` in full-height mode. This is load-bearing for every grid and is the part of the shell most easily broken by a redesign; the deliverable's definition of done says so explicitly.

**Deliberately out of scope, each with its consequence stated rather than left to be discovered:**

- **Navigation as a typed data array.** Nav stays a JSX slot: a data-driven nav would pull the `can()` filtering and the route-tree types into the shell, and ADR-0042's containment carve-out means "which entries render" is a per-app judgement, not a shell rule.
- **Command palette, global search, tenant switcher.** Named so that nobody wonders whether they were forgotten.

## The record surface

One container in three variants — `modal`, `drawer`, `page` — replacing the shells inside `app-form-surface.tsx`:

```
┌─ Header ─────────────┐  fixed: title, description, close
├─ Body ───────────────┤  scrolls: overflow-y-auto, min-h-0
└─ Footer ─────────────┘  fixed: slot — submit, cancel, destructive actions
```

Three decisions the ADR must make explicitly, because each has a wrong answer that looks right:

1. **The `<form>` element wraps header, body and footer; only the body scrolls.** This is what makes a `type="submit"` button work in a _fixed_ footer, and what lets that footer read `isPending` / `isDirty` / `isValid` through `useFormContext`. The alternative — a button outside the form carrying `form="<id>"` — needs id plumbing through every surface and still leaves the footer outside the context it needs.
2. **The container is content-agnostic.** Container and RHF frame are fused today; splitting them means the same surface serves a detail view, a confirmation with a long body, or a future wizard, and that `AppFormFrame` (ADR-0035's one form frame) renders _inside_ it rather than beside it.
3. **Sizes are a token set**, not free values: modal `sm | md | lg | xl | full`, drawer widths likewise.

Everything already decided about these shells carries over unchanged and is the surface's job to preserve: the URL is identical across all three variants and closing is a navigation ([ADR-0044](../adr/0044-record-routes-without-list-state.md)); the submit lock refuses dismissal while a mutation is in flight, including the page variant's navigation blocker; and the title is a real heading in all three — the accessibility defect `D4.2` found by testing the shells against each other.

## Decisions this deliverable needs

- **A superseding ADR for [ADR-0031](../adr/0031-ui-design-system.md).** The operator's call is that these compositions live in `@repo/ui`, and 0031 is frozen and says the opposite in as many words: _"the layout composition an app owns lives in the app, the primitives it is built from live here."_ Diverging from that is a supersession, and [ADR-0024](../adr/0024-adr-lifecycle.md) rule 1 means the successor carries **the whole** of 0031 — the shadcn ownership model, the regenerate-and-diff rule, the dependency-location rule with its three amendments, the prettier carve-out, the one-door pattern — with one section changed: what kind of code the package may hold. 0031 is 103 lines; this is the largest single writing task in the deliverable and its first step. The alternative that avoided it (a separate compositions package) was considered and rejected by the operator in favour of one door per app.
- **The shell and record-surface ADR** — the slots, the three variants, the size tokens, the form-wrapping rule, and the ADR-0037 height contract restated as this component's responsibility. Additive beside frozen [0035](../adr/0035-config-driven-resource-ui.md), [0037](../adr/0037-grid-viewport-layout.md) and [0044](../adr/0044-record-routes-without-list-state.md); if it needs any of them to say something different, that is discovered at writing time and becomes a second supersession rather than a divergence.

**Gate.** [ADR-0047](../adr/0047-ui-package-scope.md) and [ADR-0048](../adr/0048-app-shell-and-record-surfaces.md) were both written `proposed` on 2026-08-22, **ahead of** this deliverable — writing is not opening, the D4 precedent used for the fourth time, and further ahead than before: they were written while this file was still a scope document without steps. Opening D8 does not change their status. Both are **accepted at the head of `D8.1`** ([ADR-0025](../adr/0025-deliverables.md) rule 3, the per-step acceptance D4–D7 all ran on): 0047 because `D8.1` builds the compositions path and the door its changed section licenses, 0048 because `D8.1`'s `Banner` is the first composition its §3 designs. [ADR-0031](../adr/0031-ui-design-system.md) moves to `superseded by ADR-0047` in the same motion — the D5 mechanics — and stays `accepted` and in force until then. The pair governs `D8.1`–`D8.6`; `D8.7` names no ADR of its own. A step whose ADR is still `proposed` is gated and must not be started, so nothing below runs before that acceptance.

Each step names the ADRs that govern it. Read them before implementing — they carry the reasoning, this file carries the work. Every step ends green on `pnpm lint && pnpm check-types && pnpm test` and a conventional commit; `pnpm check` is the loop inside a step. Each step is sized for one agent in one sitting: the package half of each composition is separated from its adoption, because the package diff is reviewable as pure geometry and the adoption diff is where the shipped behaviour is at risk.

## Build order

### 1. The supersession lands: the compositions path, the door, and `Banner`

**ADRs:** [0047](../adr/0047-ui-package-scope.md) (accepted at the head of this step; [0031](../adr/0031-ui-design-system.md) moves to `superseded by`), [0048](../adr/0048-app-shell-and-record-surfaces.md) §1 §3 (accepted at the head of this step), [0046](../adr/0046-interface-localization.md) §12, [0023](../adr/0023-shared-contracts-package.md)

First because every later step writes into the path this one creates, and because the acceptance mechanics are heaviest here: both records accepted, the index rows updated, 0031's status flipped — done once, at the head, so the five steps that follow are ordinary building. `packages/ui/src/compositions/` opens with its smallest real occupant, `banner.tsx` — hand-written rather than built on shadcn's `alert`, which the package does not carry and which would put the banner's substrate under the regenerate-and-diff rule for no upstream benefit: variants, a `message`, an `action` slot, a `dismissible` flag, and **no `@repo/contracts` import**, the checkable boundary that keeps the shell from ever learning _why_ a banner shows (the impersonation content, the principal field and `dismissible={false}`'s first real use are all [D12](0012-impersonation.md)'s). The three coordinated edits land together as one reviewed change, exactly as `@repo/ui/ui-strings` did at D7.3: the `"./compositions/*"` `exports` entry, the pattern in `apps/admin`'s `no-restricted-imports` group, and the named re-export through `shared/ui/index.ts`. **Done when:** ADR-0031 reads `superseded by ADR-0047`, both new records read `accepted`, and the index says all three; `packages/ui/package.json` gains the `exports` entry and **no dependency** — the `dependencies` block is byte-identical; the exports entry, the lint pattern and the `shared/ui` re-export are in one commit; `Banner` renders each variant with an accessible dismiss name, hides the control under `dismissible={false}`, falls back to English with no provider mounted, and imports nothing from `@repo/contracts`; the gate is green.

### 2. The shell composition, geometry only, in the package

**ADRs:** [0048](../adr/0048-app-shell-and-record-surfaces.md) §2 §3, [0047](../adr/0047-ui-package-scope.md), [0037](../adr/0037-grid-viewport-layout.md), [0046](../adr/0046-interface-localization.md) §12

The shell before the record surface because its adoption carries the deliverable's riskiest contract — ADR-0037's height chain under every grid — and building the composition alone first is what makes that adoption a small, legible diff. `compositions/app-shell.tsx` (`"use client"`) composes the `sidebar-07` primitives and **knows nothing about routing or authorization**: `brand` / `nav` / `sidebarFooter` as the drawer's three regions, `headerStart` / `headerEnd` either side of the trigger (which stays the shell's), `breadcrumbs`, `banner`, `title` / `pageActions` as the page-header row **the single `<h1>` lives in**, `fullHeight`, and `children` inside the page container. The container carries ADR-0037's contract as its own responsibility — `min-w-0` always, `min-h-0` and `h-svh` in full-height mode — and keeps **`data-slot="page-container"` and `data-full-height` on the same element**, because three routing tests read the geometry through those two attributes and nothing else; jsdom lays nothing out, so they are the cheapest thing the new shell can be held to. The `banner` region is a `shrink-0` in-flow sibling above the header that **renders nothing at all — not an empty `div` — when handed nothing**, which is what keeps every grid page's flex budget unmoved without new arithmetic. Package tests only, within the harness's reach (a `matchMedia` stub and cleanup — no router, no form, no MSW): roles, accessible names, slot presence, the attribute pair in both modes, the empty banner's absence. The admin does not adopt it here; `apps/admin`'s only edit is the named `shared/ui` re-export.

**Done when:** `@repo/ui`'s suite asserts, per mode, the two attributes on one element; the empty `banner` slot leaves no node in the DOM; `title` renders as exactly one element with `role="heading"`; each slot's content is reachable by role or accessible name; `app-shell.tsx` opens with `"use client"` and adds no dependency; `apps/admin`'s diff is the one re-export line; the gate is green.

### 3. The admin adopts the shell

The adoption is its own step because it is where the risk concentrates: three attribute-reading tests, nine heading queries and every grid's budget all sit on this diff. `widgets/dashboard-layout` becomes a **thin adapter over `AppShell`** — it stays the `_dashboard` layout component and the `widgets`-layer shell ADR-0032 names, so the frozen record is honoured rather than diverged from: the layer supplies the contents (the typed route links and the `can()` join per ADR-0042, the principal block, the resolved `staticData.title`), the package owns the geometry. The **whole `AccountMenu` dropdown moves to `headerEnd`** — the deliberate reversal ADR-0048 §2 argues on the record: the D6.3/D7.5 grouping survives intact, `ThemeMenuItems` / `LocaleMenuItems` keep their radio-group shape and its screen-reader semantics, only the mount moves — and the customer-app requirement that justifies the slot is **written into [`docs/plan/0011-customer-app.md`](0011-customer-app.md) in the same change**, per the slot-honesty rule: a citation may not point at a sentence that does not exist. **Done when:** `dashboard-layout` renders no layout markup of its own — only `AppShell` and its slot fillers; the three routing tests reading `data-slot="page-container"` / `data-full-height` pass unchanged; the nine heading queries pass unchanged, each matching exactly one element; a test asserts the account menu opens from the header and the sidebar footer no longer carries it; `docs/plan/0011-customer-app.md` names the header-chrome requirement; "no visual regression" is recorded as pending operator acceptance rather than claimed; the gate is green.

### 4. The proved slots: breadcrumbs, and the banner's consumer

**ADRs:** [0048](../adr/0048-app-shell-and-record-surfaces.md) §2 §3, [0046](../adr/0046-interface-localization.md) §10 §12, [0036](../adr/0036-admin-testing-strategy.md)

The step that turns two slots from offered into exercised — the defect this repository has recorded twice about the `page` edit surface, and the plan carries a rule against a third. **Breadcrumbs**: the adapter composes the long-exported primitives into their first rendered screen, on the record routes, where the surface's URL gives the trail its meaning (ADR-0044). No door widening and no new string are needed — `shared/ui` has exported six breadcrumb symbols since D3.3 and the `breadcrumb` / `more` `UiStrings` keys already have a `t()` call site and an `lv` entry — and the stale "never reached the `shared/ui` door" comment in `app/providers/ui-strings.tsx` is corrected here, the step ADR-0048 assigns it to: whichever first renders one. **The banner's consumer**: the dev-only pseudo-locale notice renders a `Banner` into the slot, and **its visibility is a prop** — a `renderApp` option — with `config.VITE_I18N_PSEUDO` setting only the app's default. Gated on the config variable directly it would render in no test in the repository, because the admin vitest config pins the variable to `"false"` for the whole suite on purpose; as a prop, one test sets the option and asserts the notice, and the default suite proves the slot's absence. The notice's copy is the app's — keys in the admin's catalogues, never the package's — so ADR-0046 §14's pseudo-locale route suite stays green over it.

**Done when:** a breadcrumb renders on the record routes and is reachable as a navigation landmark; the stale provider comment is gone; a test passing the `renderApp` option sees the notice inside the banner region while the suite's default renders no banner node at all; the pseudo-locale route suite is green with the notice's keys in the catalogues; the gate is green.

### 5. The record-surface container, in the package

**ADRs:** [0048](../adr/0048-app-shell-and-record-surfaces.md) §4 §5, [0047](../adr/0047-ui-package-scope.md), [0035](../adr/0035-config-driven-resource-ui.md), [0044](../adr/0044-record-routes-without-list-state.md)

The surface's package half, separated from its adoption for the same reason the shell's was — and after the shell because nothing in it depends on the surface, while both adoptions depend on their compositions existing. `compositions/record-surface.tsx` (`"use client"`): one content-agnostic container in three variants — `dialog` | `drawer` | `page` — fixed header, scrolling body (`overflow-y-auto min-h-0`), fixed footer as a slot. **The `<form>` wraps header, body and footer with only the body scrolling**, which fights the primitives' own layout — `DialogContent` is `grid … gap-4 p-6`, `SheetContent` is `flex flex-col gap-4`, both laying out their direct children — so wrapping collapses them to a single child and **the form itself carries the row template, the `max-h` and the body's `min-h-0`**; the `asChild` / element escape exists so a `<form>` can _be_ the container's inner column while the container still owns the geometry classes. **Geometry only**: neither `react-hook-form` nor `@tanstack/react-router` enters the package — the form-state reads and the navigation blocker are the app's thin wrappers, next step. Sizes are the `sm | md | lg | xl | full` token set, mapped per variant to a class string merged through `cn` onto `DialogContent` / `SheetContent` — both already merge `className`, so sizes cost **zero generated-file edits**. Both mounts are the container's API: `open` / `onOpenChange` for the three shipped controlled dialogs, defaulted always-open for the routed mount; `dismissible={false}` refuses Escape, overlay and close alike. The structural pins are built in rather than approximated: `dialog` renders a Radix Dialog (`role="dialog"`), `drawer` a Sheet with `data-slot="sheet-content"`, `page` neither; the title is a real heading in all three (the `D4.2` defect stays closed); the close button is the primitive's own, already localized — no new string. `ConfirmDialog` is not touched: it stays on `AlertDialog`, named by the ADR as the future candidate for a confirmation with a long body.

**Done when:** the package suite asserts, per variant, the structural pin, the title's heading role, and header and footer as siblings **outside** the element carrying `overflow-y-auto`; each size token maps to a distinct class on the right content element; the controlled mount opens and closes through `open` / `onOpenChange` and the routed mount needs neither; `git diff` is empty under `packages/ui/src/components/` and `src/hooks/`; no dependency is added; the gate is green.

## Definition of done

1. **The package stayed geometry-only, checked as diffs.** `packages/ui/package.json` declares no `react-hook-form`, no `@tanstack/react-router` and no i18n dependency; `git diff` since D7's closing commit is empty for `apps/api/src`, `packages/contracts` and `docs/postman`; `packages/ui/src/components/` and `src/hooks/` carry no new uncommented divergence.
2. **The height contract held.** The three routing tests reading `data-slot="page-container"` and `data-full-height` pass unchanged, and a browser walk of both grids shows header and pager static, only rows scrolling, and no page-level horizontal scrollbar.
3. **A long form keeps its title and its Save button** in the modal and the drawer at every size token — the structural assertion (header and footer outside the scrolling element) green in both the package and admin suites, and the browser walk confirming it at real heights.
4. **All three variants are exercised.** The extended parity suite passes against `dialog`, `drawer` and the `page` variant no resource declares; the three password dialogs' controlled-mount suites pass unchanged; the nine heading queries each match exactly one element.
5. **Slots are exercised, not offered.** The account menu renders from `headerEnd`, a breadcrumb renders on the record routes, and the pseudo-locale notice renders in the banner region under its `renderApp` prop — each asserted by a test — and the D11 requirement sentence and the D9 file-count correction landed with the steps that owed them.
6. **The records agree.** ADR-0031 reads `superseded by ADR-0047`; 0047 and 0048 read `accepted` with their _Implemented_ columns filled per step; the six window documents say the same thing.
7. **Green and cached.** `pnpm lint && pnpm check-types && pnpm test` green; `pnpm test:unit` twice, the second `FULL TURBO`; `pnpm format:check` clean; a clean tree afterwards.
