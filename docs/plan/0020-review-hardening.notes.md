# D20 — Review hardening: build notes

The per-step build record of [D20](0020-review-hardening.md) — what was built, the amendments, the review findings and their fates, the gate's output, and what is pending the operator — kept apart from the executable plan so a builder opens the plan and not the journal ([ADR-0068](../adr/0068-behaviour-specs-and-plan-notes.md) §2, the plan apart from its notes). `/step` appends here; `/ship` and the close-out read it.

## `D20.1` — Accept ADR-0073; the gate runs everything

**The head.** [ADR-0073](../adr/0073-review-hardening.md) moved `proposed` → `accepted` (2026-09-17) and [ADR-0026](../adr/0026-task-graph-caching-and-serialisation.md) moved to `superseded by` for the **second** time — a delta beside [0052](../adr/0052-grid-and-admin-followups.md)'s, stated on its status line. The ADR index's topic row for the task graph gained 0073, its record rows for 0026 and 0073 were rewritten, and the conventions paragraph moved from "it is accepted at the head of `D20.1`" to the past tense naming the parent that moved. The other seven parents are deliberately untouched; they move at the steps the plan names. The ledger's D20 row and §The window say the same thing in the one place they are allowed to.

**Built.**

- **The gate's first link carries the two checks that could go red with nothing watching them.** `turbo.json`'s `lint` gains `//#test:scripts` and `//#docs:check` as dependencies, so `pnpm check` and `gate.yml`'s `pnpm lint` both run them **through the task graph** rather than as links of their own. `gate.yml` gains a paragraph saying why there is still no `run:` step for either — a CI-only script is exactly what its header refuses. Verified on the graph and not by reading: `turbo run lint --dry=json` lists both root tasks, and `@repo/ui#lint` names them among its dependencies.
- **`CLAUDE.md` trimmed to 6017 bytes**, under the 6 KB its own test asserts — which is what made that test green. The Commands block is the gate line plus the six commands a session reaches for, with setup delegated to `README.md` §Quick start; the Repo map is one line per top-level directory. Nothing a record requires it to state was dropped.
- **Coverage reported, never gated** (ADR-0073 §6): `coverage: { enabled: true, provider: "v8", reporter: ["text-summary"] }` in both shared Vitest configs, `@vitest/coverage-v8` a dependency of `@repo/vitest-config` so pnpm binds it as vitest's optional peer for every workspace. `enabled: true` is beyond the plan's three-key snippet and is not a divergence needing a record: §6 says the configs **report** a summary, and the step's own done-when demands one from a bare `test:unit`, which the snippet alone would not produce. Integration keeps no coverage — instrumenting a suite that talks to a database measures the harness.
- **The four stale `apps/web` claims corrected** — the two skills' `"use client"` sentence, and the comments in `packages/ui/src/hooks/use-mobile.ts` and `compositions/banner.tsx` reworded to name the marketing site D16 will add as future; `ui-strings.test.tsx` carried a fifth. `scripts/docs-hygiene.test.mjs` gains the case that refuses a new one in either travelling tree (`.claude/` as the machinery, `packages/ui/src` as code).
- **`README.md` §Commands**, beside them: the `pnpm check` line and a paragraph under the gate block now say what the first link carries. The two documents that describe the gate had to stop disagreeing about it in the same diff that changed it.

**Review — `adr-reviewer`, one pass, five findings; four fixed, one declined.**

- **[major, fixed] `cache: false` on both root tasks contradicted ADR-0026 §The rule.** That rule is a biconditional — "may be cached **if and only if** it is a pure function of the repository contents and the declared environment … there is no middle option" — and both tasks are pure. Left uncached, `pnpm check`'s own "cached" claim would have been half-true from this step on, and the code would have been deciding something the record already decided. Both entries are now `{}`. Proof it is real caching and not a replayed lie: a second `pnpm lint` on an unchanged tree returns `19 cached, 19 total` in **103ms `>>> FULL TURBO`**.
- **[major, fixed] `@vitest/coverage-v8` resolved to 4.1.11 against `vitest` 4.1.10**, so every unit run in the repository opened with vitest's own "Running mixed versions is not supported" warning. Pinned to `4.1.10` exactly and the lockfile refreshed; `D20.2` moves the pair together when it takes `vitest` to `4.1.x`.
- **[minor, fixed] The acceptance was dated 2026-09-14** — the day the window opened, not the day this step landed. Both statements in the ADR index now read 2026-09-17, which is the convention every earlier acceptance follows.
- **[minor, fixed] The ledger's D20 table row still called 0073 `proposed`.** The ledger is the one place window state is written (ADR-0065 §5), so a row disagreeing with the index is the defect by its own rule. The row now reads "`proposed` at opening, **accepted 2026-09-17 at `D20.1`'s head**".
- **[minor, half-fixed] The new hygiene case read _every_ file under `.claude/`**, including git-ignored `settings.local.json` — machine-dependent input, which would red the test on one clone and nowhere else, and which is exactly the impurity that would have made the caching fix above wrong. It now scans `.md`, `.ts` and `.tsx` only, with the reason in the comment. **Declined, in the same finding:** the reviewer would rather `packages/ui` said "a future Next.js consumer" than "the marketing site D16 will add", because a fork resets `docs/plan/` and the row number arrives meaningless. The plan's step text prescribes naming D16 as future, `banner.tsx` already cites `D13.7`, and `docs:check`'s step-reference rule wants a `D<n>.<step>` it does not match — so this stays as the plan wrote it. If a fork ever finds it noisy, it is a comment.

**Gate, verbatim.** `lint` 19/19 at `0 cached` (a second run 19/19, `19 cached`, 103ms `>>> FULL TURBO`) · `check-types` 16/16 · `test` 15/15 at `0 cached` · `size` 4/4 (admin js 353.9 kB of 371.1 kB, entry 163.3 kB of 171.9 kB; customer js 302.6 kB of 309.6 kB, entry 109.3 kB of 111.3 kB — all `ok`, no budget touched) · `format:check` "All matched files use Prettier code style!". Beside it, through the first link: `test:scripts` 29/29 and `docs:check` clean over the inherited documents and 13 specs.

**The coverage baseline this step makes visible**, reported and not gated, as §6 decides — `@repo/contracts` 99.26% · `@repo/crypto` 100% · `@repo/app-kit` 90% · `admin` 88.08% · `customer` 87.81% · `@repo/resource` 86.73% · `@repo/form` 81.81% · `@repo/ui` 64.59% · `@repo/grid` 63.15% · `api` 63.24% (statements; the API's number is the unit tier alone, its integration tier deliberately uninstrumented). **One false start worth recording.** The first full-gate run failed in `apps/admin` with three timed-out tests and `Error: Something removed the coverage directory "apps/admin/coverage/.tmp"` — a concurrency artefact, not a defect: the suite is green in isolation (59 files, 534 tests, 261s) and green in every gate run since. It is the only symptom seen of turning coverage on, and it appeared only while other commands were running against the same tree. Worth knowing if it recurs on a loaded machine.

**Nothing pending operator acceptance.** No browser-only geometry, no endpoint, no env key, no restart: nothing in this step touches the running stack.

## `D20.2` — Runtime advisories, pins, catalog, digests

**The head.** [ADR-0059](../adr/0059-ci-containers-and-deployment.md) moved to `superseded by` [ADR-0073](../adr/0073-review-hardening.md) for its **§3** delta only. §3 said dependencies are proposed weekly and the gate on the pull request decides, and said nothing about which version a manifest may name, where a shared version lives, or how an action is referenced — so four exact pins had no stated reason, seventeen manifests each declared `typescript`, and every `uses:` rode a moving major tag. §6's `prune` delta is `D20.5`'s and §4's Node 24 floor is `D20.3`'s, and the status line says so rather than claiming the whole record moved. The ADR index's topic row for CI gained 0073, and both record rows were rewritten.

**Built.**

- **The two runtime advisories are closed.** `nodemailer` 8 → **10.0.10** and `qs` → **6.16.0**; `pnpm audit --prod` reports "No known vulnerabilities found". `@types/nodemailer` was **deleted** rather than bumped — nodemailer 10 ships its own declarations, and a DefinitelyTyped package beside them is a second, staler answer to the same question. `apps/api/test/mail-flows.int.test.ts` is green on the new major, 56/56, and the API surface this repository uses is still the two calls the review named.
- **The pinning rule is stated where a pin is made, and it is a register.** `renovate.json` carries one rule naming **every** exact pin with its reason — `express` and `@types/express` (the type surface must describe the version installed), `typescript` (`tsc -b` writes the declarations seventeen packages check against), and `@vitest/coverage-v8` (its peer on `vitest` is an **exact version**, so the pair moves in one pull request or `.npmrc`'s `auto-install-peers` answers the unsatisfiable peer with a second copy of vitest). `tsdown` is unpinned to `^0.23.0`, which is what the rule asks for and what the review's CI-04 wanted said.
- **Four versions moved to a `catalog:`** in `pnpm-workspace.yaml` — `@types/node` (13 workspaces), `eslint` (17), `typescript` (17), `vitest` (16), the ones at or over ADR-0073 §7's ten-workspace threshold. `react`, `@types/react` and `jsdom` sit at nine and deliberately stay in their manifests. The catalog is what closed the `typescript 5.9.3` vs `^5.9.3` drift the review named; the other two (`tsx`, `@testing-library/react`) closed in the same `pnpm update -r` that refreshed the lockfile. `@repo/vitest-config` keeps its `vitest` **peer** at `^4` — a peer is a statement to consumers, and narrowing it to the version this repository happens to run would make the package lie about what it works with.
- **Every `uses:` in both workflows is a 40-hex digest** with its tag in a trailing comment, `helpers:pinGitHubActionDigests` extended in `renovate.json` so the pins keep moving, and a new `scripts/docs-hygiene.test.mjs` case refuses one without. `gate.yml`'s header says why a moving major tag is a write-access-shaped hole. A `base images` Renovate rule names `node`, `nginx`, `postgres` and `axllent/mailpit`, and **carries `matchUpdateTypes`**: Renovate applies rules in order and the last match wins per field, so an unrestricted rule there would have re-grouped exactly the majors the rule above un-groups.
- **`pnpm outdated -r` is down to `jsdom` and D21's four major families** (ESLint 10 with `@eslint/js`, Vite 8 with `@vitejs/plugin-react` 6, Vitest 5 with `@vitest/coverage-v8` 5, TypeScript 7). Everything else moved to the latest its range already allowed.

**Two deviations, both recorded in the record and not only in the code.**

- **`jsdom` is held at an exact `30.0.1`.** 30.1.0 rewrote the DOM-tree, CSS and HTML-collection internals, and under it **fourteen customer tests in four files** fail: a Radix dropdown opened in a _second_ app render of the same file never mounts its menu, so the menu query times out. Bisected rather than guessed — React 19.2.8, `@testing-library/user-event` 14.6.5, `@testing-library/dom` 10.4.1 and `vitest` 4.1.10 were each pinned back in turn and each left the failure standing; `jsdom` 30.0.1 alone made it green. Every one of the fourteen passes on 30.1.0 when run alone, which is what makes it an ordering interaction upstream rather than a defect here. The hold is an **exact version in nine manifests** because that is what actually holds it — `allowedVersions` constrains only Renovate's own pull requests — with the reproduction in `renovate.json`'s rule, ADR-0073 §7 amended to name the exception, and the plan's done-when and definition of done amended in place and labelled. It is lifted by taking a later jsdom and running `pnpm test:unit --filter customer` **whole**.
- **Both `size-budget.json` files were re-baselined and raised ~5%.** `react` is the same vendor chunk in both apps and grew **60419 → 69054 bytes (+8.6 kB, +14%)** on React 19.2.8 → 19.3.0; the rest is zod, lucide-react, the three `@tanstack` packages and react-hook-form. customer js 309767 → 327012, entry 111879 → 120324, css unmoved **to the byte** — which is what "no component changed" looks like from here. admin js 361873 → 379434, entry 166837 → 175684, css unmoved to the byte; that app was **566 bytes** under its js ceiling and **142** under its entry ceiling before the raise, so the next line of code would have tripped it. Every new ceiling is ~5% over the measurement beside it, inside the 15%-over-baseline cap ADR-0073 §5 has `D20.9` enforce, and the entry sits at 46% of the js ceiling against ADR-0062 §4's 60%.

**One more thing the bump forced, and it is in the record rather than only in a comment.** `tsdown` 0.23 renamed [ADR-0002](../adr/0002-monorepo-layout-and-tooling.md)'s `noExternal` / `external` to `deps.alwaysBundle` / `deps.neverBundle`, and defaults `platform: "node"` to a fixed `.mjs` extension. `fixedExtension: false` in both configs keeps `dist/main.js` and `dist/migrate.js` — names `apps/api/Dockerfile`, `docker/prod/compose.yaml`, the `start` script and [`docs/deploy.md`](../deploy.md) all say out loud, so the alternative was five edits to keep one filename. `deps.onlyBundle: ["postgres"]` on the API is a real whitelist rather than a silencer: `postgres` reaches that bundle through the inlined `@repo/db`, which is the arrangement 0002 describes, and anything else arriving there is now a build error. 0002 is inherited and frozen, so ADR-0073 §7 records the rename instead of editing it.

**Review — `adr-reviewer`, one pass, six findings; all six fixed.**

- **[major, fixed] `@vitest/coverage-v8` was an exact pin the pinning rule did not name**, and it is the one that bites: the installed 4.1.11 declares `"vitest": "4.1.11"` as an **exact peer** while `vitest` had just become `catalog:` → `^4.1.11`. The first lockfile-maintenance run to take vitest to 4.2 would leave the provider on an unsatisfiable peer, and `auto-install-peers` resolves that by installing a second vitest rather than by failing. It is now in the rule's `matchPackageNames` with that sentence as its reason.
- **[major, fixed] The `jsdom` exception lived in the code and the plan but not in the record.** §7 read "caret for everything else" with no exception, and the digests derive from the record. Amended in place, labelled, under the window the ledger says is open over 0073.
- **[major, fixed] The `base images` rule would have re-grouped docker majors.** No `matchUpdateTypes` meant it matched last and overrode `groupName: null` for a major — so a Node 24 or Postgres 17 bump would have arrived grouped, contradicting both its own closing sentence and ADR-0059 §3. It now names its update types, and says why in the description.
- **[minor, fixed] The tsdown rename and `fixedExtension: false` were only in code comments.** Recorded in §7's amendment, with 0002 left untouched because a fork's merge is what an edit there would cost.
- **[minor, fixed] The engines floor is understated, not merely old**: tsdown 0.23 declares `^22.18.0 || ^24.11.0 || >=26.0.0` against the repository's `>=22`. Named in `D20.3`'s step text, which is the step that moves the floor.
- **[minor, fixed] The new hygiene case read `.yml` only**, so a future `*.yaml` workflow would have escaped the digest check. It reads `/[.]ya?ml$/` now.

The reviewer also checked the four deviations rather than taking them on trust, and reported the five action digests each resolving to the commit their tag comment claims, `@types/nodemailer`'s deletion correct against nodemailer 10's own declarations, `@types/supertest` correctly kept because supertest still ships none, the catalog threshold applied consistently in both directions, and no `docs/rules/` digest citing ADR-0059 directly — so the status move stales nothing. `pnpm rules:digest` wrote 0 of 3 digests, confirming it.

**Gate, verbatim.** `lint` 19/19 at `0 cached` · `check-types` 16/16 · `test` 15/15 at `0 cached` · `size` 4/4 (admin js 370.5 kB of 389.6 kB, entry 171.6 kB of 180.7 kB; customer js 319.3 kB of 335.9 kB, entry 117.5 kB of 124.0 kB; `react` 67.4 kB of 71.3 kB in both — all `ok`) · `format:check` "All matched files use Prettier code style!". Beside it, through the first link: `test:scripts` 30/30 and `docs:check` clean over the inherited documents and 13 specs. Also green: `pnpm audit --prod` ("No known vulnerabilities found"), `pnpm install --frozen-lockfile`, `pnpm build --filter api --filter @repo/db` (`dist/main.js`, `dist/migrate.js`, no deprecation warning), `apps/api/test/mail-flows.int.test.ts` 56/56.

**One thing the operator should know.** `pnpm install --frozen-lockfile` against the **previous** lockfile failed repeatedly with `ERR_PNPM_EPERM` on `@rollup/rollup-win32-x64-msvc`'s `.node` binary — a running Vite dev server holds it open on Windows. It is not a defect in this change and nothing here needs a restart, but a rollback of this commit on a machine with the stack up will need the SPA dev servers stopped first, which is the operator's call. The stack was not touched: Postgres and Mailpit were up throughout, the API dev server was already not answering on 4000 before this step began, and the integration tier talks to the database directly rather than through it.

**Nothing pending operator acceptance.** No browser-only geometry, no endpoint, no env key. The two budget raises are the one thing worth a glance, and they are a diff of two committed files with the measurement beside every ceiling.
