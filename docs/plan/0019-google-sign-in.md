## Goal

A person signs in to the customer app, or creates an account there, through Google: plain OpenID Connect with PKCE, the ID token verified with `jose`, the callback handed to the SPA as a sixty-second fragment token the way impersonation and the verification link already are. A Google identity resolves by subject, links only to an `active` account, and creates one only where self-registration is open. An account keeps its ways in visible and under its owner's control: link, unlink with the current password, and a password set by the reset link when there is none. ADR-0072 decides all of it.

## Constraints

- `security-reviewer` reads every step's diff — the flow mints a bearer credential from an external assertion and consumes it unauthenticated (ADR-0072 §2; D13's constraint carried through D18).
- Resolution is by subject, then by a verified address against an `active` user, then creation behind `FEATURE_USER_REGISTRATION`; a `pending_verification` holder is refused and nothing is linked (ADR-0072 §1; ADR-0071 §3).
- The transaction between start and callback lives in `__Host-<APP_ID>.oidc` alone; the start is a `POST`, the callback the one navigation, and every refusal reaches the SPA as `#error=<code>` (ADR-0072 §2).
- The handoff is an `account_tokens` row, hashed, single-use, sixty seconds, consumed inside the acting transaction; the landing route strikes the fragment and asks first when a session already exists (ADR-0057 §2–§3 and ADR-0071 §1, §3 as inherited by ADR-0072 §2).
- No new auth library; the provider is a port with a real adapter and a fake, and the issuer is stubbed in tests only (ADR-0072 §2; ADR-0066).
- Link and unlink are refused under impersonation; unlink is refused as the last credential and otherwise asks the current password (ADR-0072 §3; ADR-0057 §5; ADR-0027).
- New env keys enter ADR-0004's schema, `.env.example`, `apps/api/.env.test`, `docker/prod/.env.example` and [`docs/deploy.md`](../deploy.md) (ADR-0059 §6); `VITE_FEATURE_GOOGLE_SIGN_IN` enters `apps/customer/turbo.json` as every `VITE_` key does (ADR-0033 as carried by ADR-0051).
- No Google script and no external asset in the SPA; the admin app is not touched (ADR-0072 §4; the operator's decision on the panel).
- A behaviour change updates the capability's spec in the same diff (ADR-0068 §1); new endpoints get Postman requests where a collection can reach them (ADR-0021).
- SPA copy lands in both locales (ADR-0046); `pnpm size` is measured at every SPA step and a raise is a diff of the budget file with its reason (ADR-0062 §4).
- The gate: `pnpm lint && pnpm check-types && pnpm test && pnpm size && pnpm format:check`.

## Decisions taken at scoping (operator, 2026-09-09, 2026-09-10 and 2026-09-11)

- **Users only.** Staff get no Google sign-in; how a staff row is matched waits for its own row.
- **Linking only to an `active` account**, which after D18 is an account with a proven address; a `pending_verification` holder is refused rather than activated on Google's claim.
- **The registration flag governs Google creation too.** Off means link-only; a stranger is refused with a plain sentence.
- **The OIDC transaction is a signed cookie on the API**, not a database row: it binds the callback to the browser that started.
- **A passwordless account sets a password through the reset link**, not through a session-only endpoint.
- **Unlink asks the current password** and is refused when it would leave no credential.
- **No admin screen in D19.** The admin user resource carries the identities read-only; the panel's budget lever is a row of its own.
- **Plain OpenID Connect with PKCE, `jose`, no new auth library; the issuer stubbed in tests; the browser tier does not drive the flow.**
- **The reset recovers everything** (operator, 2026-09-11, between `D19.2` and `D19.3`): a password written without the account's own authority — the reset by mail, the administrative reset — removes every federated identity, so creation stays open on any verified address and the `D19.2` narrowing is withdrawn at `D19.4`; "Set a password" is a session-minted reset link that keeps them; a passwordless account sets one before it may change its password, its address or delete itself.
