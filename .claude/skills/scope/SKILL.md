# Scope deliverable $ARGUMENTS

Turn a deliverable's scope document into a **one-page plan** the `/step` loop can execute. This is a conversation with the operator, not a fan-out: read, propose, ask only what the code cannot answer, write.

1. **Read**: the deliverable's file in `docs/plan/` (via the ledger `docs/plan/README.md`), the ADRs it names, and the code it touches. Verify every claim you are about to rely on by opening the file — never assert a count, an enumeration or a universal negative you have not just read (ADR-0050 §Altitude).
2. **Identify the real decisions** — the ones that are expensive to reverse or that steps would otherwise guess at. Ask the operator with recommended options. Everything else is the builder's call and is not written down.
3. **Spike the uncertain mechanics.** If a decision hangs on "would this actually work" (CSS chains, typing channels, API shapes), propose a timeboxed throwaway spike in a worktree instead of deciding in prose. The spike's answer becomes one sentence in the plan.
4. **Write the plan** into the deliverable's file, and an empty `<nnnn>-<slug>.notes.md` beside it — the plan holds what `/step` executes and the notes file is where `/step` writes what happened; narrative never goes in the plan (ADR-0068, the plan apart from its notes):
   - The header's `- Records:` line names every record the deliverable touches — the ones it writes, every parent they supersede, and every record it amends in place, a record a conditional step may move included — each as a linked `[ADR-NNNN](../adr/…)` reference, prose only around the links; a `- Schema: yes` or `- Schema: no` line says whether it adds migrations; and a `- Tier:` line beside it names the lane's tier — `package` (no Postgres beyond a harness's own tests, no SPA build), `api` (a lane database of its own) or `schema` (the one lane that adds migrations, always with `Schema: yes`), a short reason after the word allowed ([ADR-0082](../../../docs/adr/0082-lanes-on-one-machine-and-one-main.md), lanes on one machine and one `main`). These are what its lane file copies at opening, what [the ledger's window section](../../../docs/plan/README.md#the-window) is generated from, and what the disjointness and tier checks read ([ADR-0079](../../../docs/adr/0079-parallel-lanes.md), parallel lanes).
   - Goal (2–3 sentences), constraints (bullet list, each citing its ADR).
   - New ADRs only for genuine decisions: ~80 lines, delta supersessions per ADR-0050, `proposed`, accepted at the head of the step that builds on them.
   - Steps as a checklist, each PR-sized, each with **ADRs:** (what to read) and **Done when:** — _commands and test names only_: `pnpm check` green, a named test asserting X, a named scenario in the capability's spec under [`docs/specs/`](../../../docs/specs/), a named browser-walk item. A done-when that is an English claim about the DOM is at the wrong altitude; move it into a test the step writes.
5. **Optional single review pass**: at the operator's request, one `adr-reviewer` reading for "what would make a builder write the wrong code" — top findings, fixed once, no re-review round. Never loop.
6. Commit by explicit path, on `main` — scoping reserves the deliverable's number and its records' numbers there, serially. Opening is the operator's decision — offer it as **create the lane file**, never assume it, and name the condition in the offer: it may open beside the lanes already open only when no record it names belongs to one of them, and only if it is not a second lane adding migrations; otherwise it waits for the overlapping lane to ship (ADR-0079, parallel lanes). On the operator's yes: move the ledger row to `in progress`; write `docs/plan/lanes/D<n>.md` from the plan's header — a title line and one line each of `- Deliverable: [D<n>](../<plan>.md)`, `- Opened:` with the day's date, `- Branch:` with the lane's branch in backticks (`lane/D<n>`, or the branch a cloud session was given), `- Tier:` and `- Schema:` as the plan names them, and `- Records:` with every record of the plan's `- Records:` line as a `[NNNN](../../adr/NNNN-….md)` link, joined by `, `; then run `pnpm lanes`, which writes the list and the running paragraph of [the window section](../../../docs/plan/README.md#the-window) from the lane files, and `pnpm docs:check`, which refuses a shared record, a second schema lane, a tier the plan does not name and a stale paragraph. What the opening decided and why goes in the ledger's `How D<n> opened` section, never in the generated paragraph.

Never: multi-round refutation, zero-finding gates, counts or file enumerations in prose, done-whens a machine cannot run.
