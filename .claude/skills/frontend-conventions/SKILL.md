# Frontend conventions (condensed from docs/adr — ADRs win on conflict)

**Load [`docs/rules/frontend-and-platform.md`](../../../docs/rules/frontend-and-platform.md) first** — the generated statement of the rules currently in force for this area, each line naming its record; this document is the fuller working reference behind it. Which amendment window is open, which records are frozen and which supersession is a delta is stated in one place — [the ledger](../../../docs/plan/README.md#the-window) — and never restated here. A superseded record is out of force for what its successor names, and stands for everything the successor does not touch.

Covers `apps/admin`, `apps/customer`, `packages/ui` and the platform packages. The API side is `/api-conventions`.

## The platform packages (ADR-0051, platform extraction; ADR-0062, the shared composition) — where the machinery lives

| Package              | What it holds                                                                                                                                                                                                                         | The admin's door(s)                                           |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| `@repo/api-client`   | axios client (parameterised by segment), envelope + errors, session store, CSRF bootstrap, URL⇄query, the bulk fan-out                                                                                                                | `shared/api/*`                                                |
| `@repo/i18n`         | the `createI18n` factory, locale negotiation, Intl, the pseudo lens, `useT`/`useKeyT`                                                                                                                                                 | `shared/i18n`                                                 |
| `@repo/resource`     | `ResourceConfig`, its readers and the registries                                                                                                                                                                                      | `shared/resource/*`                                           |
| `@repo/grid`         | the v2 grid whole, its `grid` namespace, the bulk summariser                                                                                                                                                                          | `shared/grid/*`                                               |
| `@repo/form`         | the field vocabulary, the frame, ADR-0040's three shells, server-error landing, the zod locale installer, its `form` namespace                                                                                                        | `shared/form/*`                                               |
| `@repo/app-services` | theme, grid density, `can()` + capability narrowing, `route-meta`                                                                                                                                                                     | `shared/theme`, `shared/density`, `shared/auth`, `shared/lib` |
| `@repo/app-kit`      | the provider stack, the auth layout, the account-area shell, the app loader, the top-level error boundary, the router's error and not-found components, the app i18n factory, and the SPA test harness behind its own `testing` entry | `shared/app`, `shared/ui`                                     |

- **A door is the only path to those symbols**, not necessarily one slice per package — `@repo/app-services` has four, because that is where its pieces already lived and the density is the theme's sibling rather than part of it. `no-restricted-imports` refuses every package path outside its door, and **each door block re-declares the groups it is _not_ the door for**; an exemption wider than its reason is the same defect as a block missing a group.
- **What stays in the app is the dictionary and the data**: the i18n catalogues and namespace list, the `errors` catalogue's readers, `RESOURCE_POLICY`, `shared/config`, and the `meta`/`CustomTypeOptions` augmentations that are keyed by this app's own `TranslationKey`.
- **A package that renders copy ships its own namespace** and exports `bundles` (its `en`) plus its own `loadCatalogue`; the app composes them into `createI18n`'s `resources` **at `init`** (ADR-0046 §13 as amended). `register` is for a namespace genuinely learned late — `addResourceBundle` on a live instance re-renders every bound component, which loses state mid-gesture.
- **A package that reads a property must own the property**; one that only names a type (`TranslationKey`) can leave it to declaration merging. That is why `StaticDataRouteOption` moved with `route-meta` and `query-meta.ts` did not.
- `@repo/ui` is unchanged by all of this: it stays presentation-only on §12's `UiStrings` (ADR-0047).

## Layers (ADR-0049, admin app architecture) — FSD, and the direction is lint-enforced

```
app  →  pages  →  widgets  →  features  →  entities  →  shared
```

```
src/app/        providers, routes/ (file-based), routeTree.gen.ts — wiring only
src/pages/      one slice per screen; thin composition
src/widgets/    self-contained blocks reused across pages (dashboard-layout, app-sidebar)
src/features/   interactions that change something (a form, a dialog, a mutation)
src/entities/   domain resources: query hooks, key factory, resource UI config
src/shared/     api/ ui/ form/ grid/ resource/ notifications/ lib/ config/ — no domain knowledge
```

- **Only downward, never sideways.** `eslint-plugin-boundaries` + `eslint-import-resolver-typescript` enforce it; a feature importing another feature, or anything importing from `app`, is a lint error. A pattern two features want gets _demoted_ into `entities`/`shared` or promoted to a widget.
- **Slices have a public API**: import `@/entities/staff`, not `@/entities/staff/staff.api`. Colocated tests are one exception and **`shared` is the other** — its slices are the app's own toolbox and are imported by path (`@/shared/grid/app-grid`), which the lint config states explicitly.
- **A hook two layers need lives in `shared`, not beside its provider** — `useApiClient`/`useSession` are in `shared/api/context` precisely because a feature may not reach into `app`.
- Routes are TanStack Router file-based: `_auth.*` (unauthenticated) and `_dashboard.*` (guarded in `_dashboard.tsx`'s `beforeLoad`). Adding a page under `_dashboard/` inherits the guard. `staticData: { title }` per route.

## Design system (ADR-0047, UI package scope and compositions)

- shadcn/ui (`new-york`) on Tailwind v4, owned as source in `packages/ui`; no build step. **The palette is no longer shadcn's `neutral`**: it is ADR-0054's design language **"Instrument"** — see below. `components.json` still says `"baseColor": "neutral"` in both packages and **stays that way**: it is what the CLI generates _against_, and a generated primitive names semantic classes rather than palette values, so the sheet is the palette and this field is the generation basis. Do not "fix" one to match the other.
- **The design speaks through exactly three surfaces (ADR-0054)**: the token sheet `packages/ui/src/styles/globals.css`, the hand-written compositions, and `@repo/grid`'s own styling. A design need none of the three can meet is an owned edit with the comment ADR-0047 regime 1 requires, or a finding for the ADR — never a quiet restyle of a generated primitive.
- **The tokens (ADR-0054 §2, both themes in one sheet).** Every neutral and the primary on hue 258–264, neutral chroma ≤ 0.014; `--radius: 6px` with the scale sm 4 · md 5 · lg 6 · xl 8 and nothing rounder than 8. Dark borders are **solid, never alpha**, over a lifted floor — sidebar `0.165` < background `0.185` < muted `0.205` < card `0.215` < popover `0.235` is a readable elevation ramp. Four tokens beyond shadcn's set, each with a `--color-*` mapping so a utility exists: `--primary-tint` (selected rows, active nav, chips), `--border-strong` (band rules), `--success` and `--warning` (status dots). **Colour, radius, type and spacing come from tokens**; a raw hex or an arbitrary `oklch()` in a component is the defect.
- **Fonts are self-hosted (ADR-0054 §1)**: IBM Plex Sans 400/500/600 and IBM Plex Mono 400/500 through `@fontsource`, imported by each app beside its stylesheet — not Google's CDN (visitor IPs, an external runtime dependency, offline dev and e2e). `--font-sans`/`--font-mono` are mapped in `@theme`, so Tailwind's preflight restyles the app from the token sheet alone. Mono is for identifiers, emails, timestamps and counts.
- **Where a generated primitive spells a value, the primitive wins** — ADR-0047 keeps `src/components/` byte-identical, so ADR-0054 records what ships rather than the code disagreeing with it (both §2 amendments). Two live cases: the **focus ring** is `ring-ring/50 ring-[3px]` in seven components, so the width is the design's and the opacity is 50% of `--ring`, not 20%/28%; and the **radius assignment** (checkbox 4 / badge·chip 5 / controls 6 / card·dialog·popover 8) is reached only from the surfaces that own each shape — `@repo/grid` for badges and chips, `RecordSurface` for the dialog, drawer and page card — while buttons, inputs and selects keep the CLI's `rounded-md`. The base and the 4·5·6·8 scale are the token sheet's and are already right.
- **Two kinds of code under two regimes, and the path says which.** `src/components/` and `src/hooks/` are **generated primitives**: prettier-exempt, byte-identical to the CLI output, upgraded by regenerate-and-diff, and an edit to one carries a comment naming the rule that forced it (that comment cites ADR-0047 (UI package scope and compositions); the existing ADR-0031 (shadcn/ui design system) citations stand as history and are not swept). `src/compositions/`, `src/ui-strings.tsx` and `src/lib/` are **ordinary owned code**: formatted, reviewed, tested in `src/__tests__/`, edited rather than regenerated.
- **Add a primitive with `/ui-component`.** `npx shadcn add <x>` run from `apps/admin` lands it in `@repo/ui` via `components.json` aliases — then move the radix dependency it installed into `packages/ui`.
- **A composition is a layout every app of this shape is built from** — the shell, the record-surface container, `Banner` (ADR-0048). It is **presentation-only**: geometry, slots, size tokens and accessible structure, with **no `@repo/contracts` import** and no knowledge of routing, authorization, forms, server state or the session; content arrives through slots. A composition an app _owns_ — a screen, a widget joined to a session — still lives in the app.
- **The dependency list does not grow for compositions.** No `react-hook-form`, no `@tanstack/react-router`: the record container is geometry-only, and `AppFormFrame` and the page blocker stay in `apps/admin` as thin wrappers. **A composition carries no `"use client"`** — no consumer is a server-component framework, and one that needs the boundary reintroduces it by its own record (ADR-0074 §7, no client directive).
- **One door**: every layer above `shared` imports design-system components from `@/shared/ui`, never `@repo/ui/components/*` or `@repo/ui/compositions/*` (lint enforces it). The door is named re-exports only; a component with behaviour of its own is a file beside the door (`app-loader`, `confirm-dialog`, `query-error`). **A new export path costs two edits when the path opens** (the `exports` entry and the lint pattern) **and one per symbol** (the named re-export, which lands with the symbol). The rule runs both ways: a re-export whose _last_ consumer in an app leaves is removed by the step that removes it, and a colocated test counts as a consumer.
- `lucide-react` may be a direct app dependency (icons are authoring, not design system); every other primitive dependency stays in `packages/ui`.
- **`packages/ui` has no `no-literal-string` rule** — it lints with the plain React config — so the `UiStrings`-only rule for composition copy is review-enforced here, not lint-enforced.

## Session and the API client (ADR-0033, browser API client and session; ADR-0030, CSRF bootstrap endpoint; the code lives in `@repo/api-client` per ADR-0051, platform extraction)

- **Credentials live in memory only.** No access token, CSRF token or principal in `localStorage`, `sessionStorage` or a client-set cookie; the client never _reads_ `document.cookie`. Non-credential display state may be persisted, and there are three: the theme, the sidebar's cookie, and ADR-0041's grid preferences. A fourth cites the same carve-out rather than treating persistence as normalised. Since ADR-0045 the theme and the grid preferences are **account** facts held server-side, and `localStorage` is the cache in front of them — the carve-out still describes what may sit on the device, not who owns the value.
- Boot: `GET /auth/csrf` → `POST /auth/refresh`; the app renders nothing until it resolves. A failed refresh is `anonymous`; a failed bootstrap is "API unreachable" and is shown.
- One axios instance in `shared/api/client.ts`: bearer on every request, CSRF header on the three guarded paths, `X-Auth-Transport: cookie` on login/refresh, **single-flight** refresh on `401`, one bounded retry each for `401` and `403 CSRF_TOKEN_INVALID`, terminal codes end the session. Absolute URLs are refused.
- `client.ts` is the only writer of tokens. `useSetPrincipal` is the one narrow exception, for a profile rename.
- Failures are `ApiClientError` carrying a contracts `ErrorCode`; nothing branches on status alone.
- `apps/admin/.env` is its own file. Everything `VITE_*` is compile-time public — nothing secret, ever.

## Server state (ADR-0043, one query language for both the URL and the wire)

- **TanStack Query owns all server state**; component state owns nothing a server sent.
- Query keys come from a per-entity factory (`staffKeys.list(params)`). Never inline a key array.
- **List state lives in the URL, spelled in the API's own query language** (0043). `validateSearch: listQuerySearchSchema`, `stripSearchParams(listSearchDefaults)`, and the parsed search _is_ the query key — all unchanged. What changed is the characters: there is **one serialization**, `@repo/contracts`' `stringifyListSearch`/`parseListSearch`, used by both the axios `paramsSerializer` and the router's `parseSearch`/`stringifySearch`. So `/staff?offset=40&sort=-email&filter[status]=active` is what the address bar shows **and** a valid query string for `GET /api/v1/admin/staff`. Brackets are written literally; a `like` pattern's `%` stays `%25`.
  - The codec is installed on the **router**, never on a route, because `validateSearch` must round-trip its own output (a finding, not a preference). It touches only the names `LIST_QUERY_PARAMS` defines and delegates the rest, so `/login?redirect=…` is untouched.
  - Test it **at the seam** — apply through the UI, read `router.state.location.searchStr`, mount a fresh router at that URL. A codec round trip alone was proved insufficient.
- **Queries are silent** (no toast) and therefore **must render their own failure** — `QueryError` in the place the data would have been, with a retry.
- **Mutations declare outcomes in `meta`**, and one global cache handler delivers them: `meta: { success: "…" }`, `meta: { errorToast: false }` where a form renders the failure inline. No `toast()` at a call site for a CRUD outcome.
- Invalidation: a mutation invalidates **its own entity's** keys (`lists()` + `detail(id)`); the **feature** invalidates whatever else the interaction touched (an entity may not import another entity). The test: does the response of any cached query change because of this write?
- A mutation whose variables carry a plaintext credential spreads `CREDENTIAL_MUTATION` (`gcTime: 0`) from `shared/api`.

## Resource UI (ADR-0035, config-driven resource UI, as carried by ADR-0063, typed resource configs)

- **One `ResourceConfig` per resource**, in its entity slice: `columns`, `fields`, `errorFields`, written **`as const satisfies ResourceConfig<TRow, TCreate, TUpdate>`** — the resource type and the two bodies from `@repo/contracts` (ADR-0063 §1). Columns are keyed by the row plus the reserved `actions`, fields by either body, and `errorFields` by either body, so a misspelt column or a field the endpoint dropped is a compile error. A resource with no grid (a singleton like the profile) declares a `FieldConfigMap<TBody>` alone.
- **Configs are data.** Names, labels, initial values and registry _keys_ — never functions. Implementations live in named registries (`shared/grid/registry.ts`, `shared/form/registry.ts`); a typo'd key is a compile error.
- `AppGrid` is TanStack Table v9 in fully manual mode over shadcn `Table`: the engine sorts, filters and paginates nothing. A header click writes the URL, the query refetches.
- **Every `sortable`, every `filter`, every hot filter and `grid.searchable` is a claim about the endpoint's `listQuerySchema`** — the half no type can reach — and a resource's `__tests__/<x>.config.test.ts` is **one call of `assertConfigMatchesContract`** (ADR-0063 §2), passing the endpoint's `listQuery`, both bodies, `samples` for the fields whose values are domain-shaped, and `optionLabelled` from the app's catalogue. Both directions are checked, and the negative controls live in `@repo/resource`'s own suite. Do not hand-write a per-resource claims suite.
- Forms are React Hook Form with `zodResolver(<the contracts schema the API validates with>)`; `AppFormDialog` is the frame (both providers, the `fieldset disabled aria-busy` lock, `AppFormError`, no dismissal mid-flight); edit submits are pruned to `dirtyFields`.
- **Layout is JSX, config is what a field is.** The day config grows a `layout` key, ADR-0035 (as carried by ADR-0063) needs superseding.
- Server failures: `applyServerErrors(error, form.setError, { fields: <this variant's names>, codeFields, messageForError })`. It lands a `VALIDATION_ERROR` detail on its field verbatim (the detail's words are the contract's) and everything else at the form level through the code catalogue. `messageForError` comes from `useMessageForError()` and is **required** — a defaulted English would be a form whose fields are translated and whose form-level failure is not.
- Operator-facing copy: **codes** are catalogued in `shared/i18n/locales/en/errors.json`, keyed by `ErrorCode` (the old `Record<ErrorCode, string>` moved, and its compile-time completeness moved with it to `shared/i18n/__checks__/errors.ts`, so a new code still fails `check-types` until someone writes a sentence); **field rules** are catalogued in the contracts schema. The API's own `error.message` is never rendered.

## The data grid, v2 (ADR-0037, grid viewport layout, as carried by ADR-0054, design language "Instrument"; ADR-0038, selection and capabilities; ADR-0039, filter UX; ADR-0040, record surfaces, as carried by ADR-0044; ADR-0041, grid preferences; ADR-0042, client-side authorization)

Everything below is additive over ADR-0035; the config is still data and the server still owns every data operation.

- **The shell (ADR-0037; its _visual frame_ is ADR-0054 §4 — every mechanic below stands).** A grid page opts in with `staticData: { fullHeight: true }`, and **every wrapper from the page container down to `AppGrid` carries `flex flex-col flex-1 min-h-0`** — one missing link and the budget reverts to document scroll and the sticky header comes unstuck. Nothing on that path may clip: an `overflow-hidden` that looks tidier silently eats the pager on a short viewport. One scroll container, sticky header, static pager, `min-h-64` floor, and below the floor the page scrolls rather than the grid crushing.
- **Record surfaces are routes (ADR-0044, a record URL carries only the record).** `/<x>/new` and `/<x>/$id`, detail data through the route loader (`ensureQueryData` on the entity's own `detail(id)` key). **A record URL carries only the record** — no `retainSearchParams`, nothing after the id. The list state travels as **history state** through `shared/grid/record-navigation` (`openState` at the entry point, `closeSearch` on every close), which survives reload and Back and is absent for a cold link, so a record someone sent you closes to the bare list. The grid behind a dialog or drawer reads `useCarriedListState`, **not `useSearch` alone** — the parent's search while a record is open is the record URL's, so reading it directly floats the overlay over page one of everything. The list route needs an **index leaf the grid does not live on**, or opening a dialog unmounts the grid behind it. `grid.editSurface: "dialog" | "drawer" | "page"` picks the shell and **the URL is identical across all three**. Destructive confirmations and the password ceremony stay ephemeral component state on purpose — a URL must not reopen a "confirm delete".
- **Capabilities (ADR-0038) and `can()` (ADR-0042) are different questions.** `grid: { selectable, canCreate, canEdit, canDelete, canBulkDelete }` says what _this surface offers_; `useAllowedCapabilities(config.grid, "<resource>")` conjoins it with the operator's role **once per screen**, so `shared/grid` never learns a resource name. The API's guards remain the enforcement — none of this is a security boundary. Containment actions (reset password, sign out everywhere, and the edit form that hosts disabling) render for everyone deliberately: a hidden break-glass control during an incident is worse than a refused one. Bulk delete is a feature-owned `Promise.allSettled` fan-out — bounded concurrency, stops dead on `RATE_LIMITED`, one summary with per-item refusals.
- **Filters (ADR-0039).** There is no filter row. A column that declares a `filter` gets a **header icon opening a dialog that commits on Apply**; `grid.hotFilters` are toolbar stances, `enum` or `presence` only, because a button is a choice and not a composition surface. The applied-filters bar renders **from the URL's validated filters, never from the column configs** — configs contribute labels, never membership — so a deep-linked filter on a field no column owns still shows and still clears. **Every applied filter gets a chip, hot ones included** (ADR-0052 §Visible state): ADR-0039 suppressed the chip while a hot-filter button displayed the same entry, and that rule is retired — the bar is the inventory, and the duplication is accepted. Rows stripe only where a page passes `striped`, off by default; the resize handle carries a `bg-border` grip at rest.
- **Preferences (ADR-0041).** `gridId={config.name}` turns on column sizing, order and visibility. The taxonomy is the rule to cite when new grid state asks where it lives, and it is three-way: **the URL owns _view_ state, preferences own _ergonomics_, history state owns _the way back_, and the table owns nothing durable.** Sizing never enters a link — a shared view must not impose the sender's column widths on the receiver. Storage is behind a three-function adapter; the value is versioned, bounded and reconciled against the config on read, so a column rename is never a migration. The schema itself now lives in `@repo/contracts` and is re-exported from `shared/grid/preferences.ts` (ADR-0045, user settings).
- **Settings are the second adapter behind that seam (ADR-0045, user settings).** `entities/settings` owns the account's `theme`, `locale` and `grids`; `createServerPreferenceAdapter` implements the same three `PreferenceStorage` functions over an in-memory mirror seeded by the settings query, and one debounced writer coalesces every change into a single `PATCH /settings`. It is supplied through `PreferenceStorageProvider` in `shared/grid`, so **`createGridPreferences` and `AppGrid` did not change and must not**. The adapter owns the `machxi.admin.grid:<gridId>:v1` ↔ `grids[gridId]` mapping; the store never learns a `gridId` is on the wire. Signed out, the local adapter is used alone — read that from the **session**, not from whether the query has data. A local-only entry is adopted on its first read and uploaded once; a server entry wins; an entry either schema refuses is discarded rather than repaired, on the device and on the wire.
- **Structural columns are the grid's, not the resource's.** The selection checkbox and any column whose `cellRenderer` is `rowActions` are pinned first and last by `AppGrid`, absent from the Columns menu, and never hidden, reordered, resized or stored.

## Localization (ADR-0046, interface localization)

- **`shared/i18n` is the seam, and `createI18n` is a factory** — never a module-level singleton. `app/providers/i18n.tsx` builds one instance inside `SettingsProvider` and hands it to `I18nextProvider`; the harness builds its own per render. The module lifts into a platform package unchanged, so nothing under it may learn which app mounted it.
- **Locale precedence, in order: the account's `settings.locale` → `localStorage` `machxi.admin.locale` → `navigator.languages` → `en`.** `lv-LV` matches `lv` by primary subtag; anything else is **not guessed at**. `Accept-Language` is used nowhere, by either side. The pure half is `resolveInitialLocale` and it is table-tested.
- **`en` is bundled eagerly** — it is the fallback, the type source and the locale the suite runs in — and every other locale is one dynamic `import()` per `<locale>/<namespace>.json`. No `public/locales`, no runtime fetch: catalogues are code.
- **Keys are typed, and configs carry them.** `types.d.ts` declaration-merges the `en` catalogue into `CustomTypeOptions`, so a missing or misspelled key is a `check-types` failure. A `ResourceConfig`'s `header`, `label`, `description`, `placeholder` and filter labels, a route's `staticData.title`, a mutation's `meta.success` and `AppGrid`'s `emptyMessage` are all `TranslationKey`s — **a key is data**, so ADR-0035's config-is-serializable rule is unmoved. The rendering machinery resolves them with **`useKeyT()`** (`TranslateKey`, every namespace), never a namespace-bound `useT("x")`, because `shared/*` may not learn which resource it is drawing. A module whose copy is all one namespace's keeps `useT("grid")`; a module that resolves keys **it did not write** takes the app-wide one and prefixes its own (`t("grid:chip.is")`).
- **One `locales/` tree, one namespace per slice, and the namespace name _is_ the slice name.** Ten of them: `common`/`grid`/`form`/`errors` are the cross-cutting four that belong to `shared/*`, and `auth`/`dashboard`/`profile`/`staff`/`users`/`settings` belong to the slices they are named for (`settings` holds theme and locale copy). A `staff:` key used in `features/users-manage` is a review finding — lint cannot see a string prefix, and ADR-0046 says so rather than pretending it can.
- **An enum value's label is `common:options.<value>`, composed at runtime** (`optionLabel`, `dynamicKey`) with `humanize` as the fallback — the one composed key in the app, because `StatusBadge` and `RolesList` get a cell value and no config, and because spelling the members out would copy a contracts tuple ADR-0023 declares once. Each config test asserts every option it declares has a catalogue entry; the compiler cannot.
- **A namespace that is not the app's is declared through `ResourceNamespaceMap`, never `CustomTypeOptions`** — the test fixture already does it (`src/test/fixtures/demo-i18n.d.ts` + `addResourceBundle` in the harness), and it is the rule the platform packages follow.
- **`en` means en-GB**, and `INTL_TAGS` (`en → en-GB`, `lv → lv-LV`) is the only place a locale becomes a formatting tag. `<html lang>` carries the tag. Never `toLocaleString()`/`toLocaleDateString()` with an implicit locale anywhere in `apps/admin`.
- **The mechanical half is lint and tooling.** Type-aware `no-literal-string` ships in the shared `@repo/eslint-config/admin` export; `pnpm i18n:check` and `pnpm i18n:extract` are a hand-written scan rather than `i18next-parser` — `en` is the type source, so the tool only ever deletes and the compiler owns the other direction; `i18next-pseudo` sits behind `VITE_I18N_PSEUDO`, and a suite walks every route of the generated tree under the pseudo-locale. `@repo/contracts/locales/lv` answers zod's three `.refine()` sentences through a source map installed at `z.config({ customError })`, and `applyServerErrors` prefers its own re-derived message over the wire's English. The `lv` catalogues across every namespace are marked `pending native review`. `@repo/ui` gets its English defaults through `UiStrings` (thirteen keys, on the `shared/ui` door and in the `no-restricted-imports` group with it), fed from `common:ui.*` by `app/providers/ui-strings.tsx`, so the design system still names no i18n dependency. The locale switch and the theme control live in `/account/preferences` (ADR-0053 §2, the account area). The API is **untouched** by any of it.

## Testing (ADR-0036, admin app testing strategy)

- Vitest + Testing Library + MSW (`msw/node`). **No live-API tier**; an unhandled request is an error.
- Handlers are built from `@repo/contracts` — parse the request with the schema the API validates with, answer through the envelope builders. A handler modelling a refusal names the service function it mirrors, and must never be more permissive than it.
- `renderWithProviders` for a component; `renderApp` for anything about routing (real generated route tree on a memory history). Every dependency is passed, never `vi.mock`ed. Both take a **`locale`, default `en` loaded synchronously**, and return the instance as `i18n` — assertions stay by English accessible name, which is what keeps the suite unmoved as locales are added.
- Query by **role and accessible name**. A control the suite cannot name is one a screen reader cannot name.
- Cover: config-versus-contract (columns **and** hot filters, every declared option), the URL↔query round trip, form validation and server-error placement, the submit lock, and each session state (bootstrapped, expired-and-refreshed, terminal).
- **Grid preferences are tested at two levels, and they use different storage on purpose.** The store's own suite runs against an in-memory `PreferenceStorage`, which is what the adapter seam is for; a _page_ suite exercises the real wiring (`gridId={config.name}` reaching the real adapter) and therefore writes real `localStorage` — so it clears `localStorage` in `beforeEach`, or one case's column arrangement is handed to the next and the file's result depends on its order.
- **Close an overlay before unmounting.** A test that unmounts with a Radix popover or dialog open leaves its dismiss layer mutating the document; nothing fails, and every `findBy*` after it re-scans a tree that never settles. It cost one file 656 s before anyone noticed.
- jsdom has no layout, so **geometry is not testable here** — widths, wrapping, sticky positioning and scroll behaviour are the manual walk's, and the walk is what has caught every layout defect so far.

## Commands

```
pnpm dev --filter admin          # http://localhost:3001 (needs the API on 4000)
pnpm check                       # fast loop: lint + check-types + test:unit, one cached parallel run
pnpm test:unit --filter admin    # admin's unit suite alone, cached, no database
pnpm test:e2e                    # the browser tier, beside the gate and never in it
```

The gate itself is defined once, in `CLAUDE.md` §Commands, and every change ends green on it. Its `size` link weighs each SPA's build against its own budget and is cached, so it costs nothing when the build has not changed.
