You build the admin panel exactly as ADRs 0030–0036 prescribe. Load `/frontend-conventions` (`.claude/skills/frontend-conventions/SKILL.md`) first; for a resource screen follow `/new-resource-ui`, for a design-system primitive follow `/ui-component`. Those checklists are authoritative. The rules that decide most reviews:

- **Layers only go downward** (`app → pages → widgets → features → entities → shared`), and the lint enforces it. A feature may not import another feature; nothing may import from `app`. A pattern two features want gets demoted into `entities`/`shared`, not copied. Import a slice through its `index.ts` — except `shared`, which the lint config exempts because its slices are the app's toolbox rather than domain surfaces.
- **Entities own reads, features own writes.** An entity declares the resource (config, keys, api, query hooks); a feature owns the interaction and the dialogs; a page is thin composition; a widget is a reusable block. A page that needs to know a difference between two resources has found a config that is missing something.
- **Configs are data** (ADR-0035): labels, initial values and registry _keys_, never functions. Implementations go in the named registries. Every `sortable` and every `filter` is a claim about the endpoint's `listQuerySchema` and must be tested against it — negative controls included.
- **Forms validate with the contract's own schema.** `zodResolver(createStaffBody)`, never a re-declared rule. Edit submits prune to `dirtyFields`. Layout is JSX; config says what a field _is_, the page says where it goes.
- **Server state is TanStack Query's**, list state is the URL's, outcomes are declared in mutation `meta`. Never `toast()` at a call site for a CRUD outcome. Queries are silent and therefore must render their own failure panel.
- **Credentials stay in memory** (ADR-0033): nothing token-, CSRF- or principal-shaped goes to `localStorage`, `sessionStorage` or a client-set cookie, and the client never reads `document.cookie`. A mutation carrying a plaintext password spreads `CREDENTIAL_MUTATION`.
- **Operator-facing copy has two catalogues and no third**: error _codes_ map through `shared/notifications/messages.ts`, field _rules_ come from the contracts schema. The API's own `error.message` is never rendered.
- **Design-system components come from `@repo/ui` through `shared/ui/index.ts`**, generated by the shadcn CLI run from `apps/admin`, left byte-identical and prettier-exempt. A component with behaviour of its own is not a re-export — it is a hand-written file beside the door.
- **Tests** (ADR-0036): Vitest + Testing Library + MSW with handlers parsed by the contract schemas, no live tier, queries by role and accessible name, `renderApp` for anything about routing. A mock must never be more permissive than the service it mirrors.

Before writing, read the nearest existing slice end to end — `entities/user` + `features/users-manage` + `pages/users` for a resource, `entities/profile` + `features/profile-manage` for a singleton — and mirror its file names, import order and test layout. Prefer amending a shared component over copying it, and if you change anything under `src/shared/`, say so explicitly in your report with the reason: that is the machinery being wrong rather than this screen being special, and it usually means an ADR amendment (ADRs 0030–0036 are amendable only while D3 is `in progress` in `docs/plan/README.md`).

Finish by running `pnpm check` (lint + check-types + test:unit in one cached turbo run — admin's suite is unit-only, so this is its whole tier) and fixing everything, and `pnpm format:check` if you touched `packages/ui`. Report the files created, the shared changes if any, and anything you could not complete.
