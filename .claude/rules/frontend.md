# Admin app and design system (ADRs 0030–0050)

Loaded when you touch `apps/admin` or `packages/ui`. Read `/frontend-conventions` before writing code here; the ADRs are the source of truth. **ADRs 0030–0050 are frozen** — D7 shipped 2026-08-22 and D8 2026-08-27, so a divergence from any of them is a superseding ADR, never an edit; **0051 is amendable in place while D9 is `in progress`** in `docs/plan/README.md`, labelled `**Amended YYYY-MM-DD (D9.n).**`. **0031 is superseded by 0047, 0032 by 0049, 0024 by 0050, and both 0033 and 0049 by 0051** (0051 accepted 2026-08-27 at `D9.1`). 0034 and 0040 are superseded too (by 0043 and 0044). A superseded record is out of force: read its successor.

- **Design system** (0047, superseding 0031): shadcn/ui in `@repo/ui` on Tailwind v4, reached only through the `shared/ui` door. Generated primitives under `packages/ui/src/components/` and `src/hooks/` stay byte-identical to the CLI output (prettier-exempt); an edit to one must earn itself with a comment naming the rule that forced it. **Hand-written compositions live in `packages/ui/src/compositions/`** under the ordinary code regime — formatted, tested in `src/__tests__/`, edited rather than regenerated — and are presentation-only: no `@repo/contracts` import, no routing, no forms, no session, and the dependency list does not grow for them. `@repo/ui` gains no i18n dependency — its operator-facing strings come through the `UiStrings` context (0046), which makes any composition with micro-copy a `"use client"` component.
- **Architecture** (0049, superseding 0032; superseded by 0051 for the `shared/` tree — those slices are doors over packages now): FSD layers `app → pages → widgets → features → entities → shared`, downward-only imports lint-enforced, TanStack Router file-based routes; an entity may not import another entity — the feature layer is where two entities meet. `widgets/dashboard-layout` is a thin adapter over `@repo/ui`'s `AppShell` and the account menu lives in the shell's header, not the sidebar footer (§The-shell-adapter).
- **Process** (0050, superseding 0024): a superseding ADR states the delta and carries the parent's untouched sections by reference; an ADR records decisions, not counts or enumerations a compiler could check; verification is the deterministic gate plus **one bounded review pass per step on the diff** — no refutation rounds.
- **Session** (0033, superseded by 0051 — the decisions stand, the code moved to `@repo/api-client`): credentials in memory only — no token, CSRF token or principal in `localStorage`, `sessionStorage` or a client-set cookie; non-credential display state (theme, locale, grid preferences) may be persisted; single-flight refresh; CSRF via the 0030 bootstrap endpoint; the client never _reads_ `document.cookie`.
- **Server state** (0043): TanStack Query owns all server state; per-entity key factories, never an inline key; outcomes declared in typed mutation `meta` and delivered by one global handler; queries are silent and render their own failure panel. **List state lives in the URL in the API's own query language** — `?sort=-email&filter[status]=active` — through the one codec in `@repo/contracts`; a record URL carries only the record, and the way back travels as history state through `shared/grid/record-navigation` (0044).
- **Resources** (0035): one `ResourceConfig` per resource — serializable config plus named registries — for both `AppGrid` (TanStack Table v9, manual mode, over shadcn `Table`) and config-driven RHF forms over the contracts zod schemas; every field disabled while a mutation is pending. Copy in a config is a translation key (0046).
- **The v2 grid** (0037–0042, 0044, 0045): a grid page is a height budget with one scroll container, a sticky header and a static pager, every wrapper down to `AppGrid` carrying `flex flex-col flex-1 min-h-0` and nothing on that path clipping; `grid` capability flags say what a surface _offers_, `can(action, resource)` says who may use it, conjoined once per screen so `shared/grid` never learns a resource name; bulk delete is a bounded client-side fan-out with per-item refusals; no filter row — a filterable column gets a header dialog that commits on Apply, `grid.hotFilters` are toolbar stances, and the applied-filters bar renders from the URL, never from the configs. **The URL owns view state, preferences own ergonomics, history state owns the way back, the table owns nothing durable.** Preferences, theme and locale are an account fact in `settings` with `localStorage` as the cache in front; the store never learns a `gridId` is on the wire.
- **Copy has two catalogues, both localized** (0046): error _codes_ in the `errors` i18n namespace (typed complete over `ErrorCode`), field _rules_ as zod's own messages through the client-side error map (`lv` map in `@repo/contracts/locales`); the API's `error.message` is never rendered. Every operator-facing string is a typed i18next key — a literal in JSX fails lint. `en` means en-GB; `lv` is machine-drafted pending native review.
- **Testing** (0036): Vitest + Testing Library + MSW with handlers derived from `@repo/contracts`; no live-API tier; a mock more permissive than the service certifies the opposite of production. Assertions by accessible name in English; the pseudo-locale suite proves no literal survived.
- **Invalidation**: a mutation invalidates its own entity's keys; the feature invalidates whatever else the interaction touched.
