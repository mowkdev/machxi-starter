# Admin app and design system (ADRs 0030–0046)

Loaded when you touch `apps/admin` or `packages/ui`. Read `/frontend-conventions` before writing code here; the ADRs are the source of truth. ADRs 0030–0045 are frozen; 0034 and 0040 are superseded (by 0043 and 0044) and out of force.

- **Design system** (0031): shadcn/ui in `@repo/ui` on Tailwind v4, reached only through the `shared/ui` door. Generated primitives under `packages/ui/src/components/` stay byte-identical to the CLI output (prettier-exempt); an edit to one must earn itself with a comment naming the rule that forced it. `@repo/ui` gains no i18n dependency — its operator-facing strings come through the `UiStrings` context (0046).
- **Architecture** (0032): FSD layers `app → pages → widgets → features → entities → shared`, downward-only imports lint-enforced, TanStack Router file-based routes; an entity may not import another entity — the feature layer is where two entities meet.
- **Session** (0033): credentials in memory only — no token, CSRF token or principal in `localStorage`, `sessionStorage` or a client-set cookie; non-credential display state (theme, locale, grid preferences) may be persisted; single-flight refresh; CSRF via the 0030 bootstrap endpoint; the client never _reads_ `document.cookie`.
- **Server state** (0043): TanStack Query owns all server state; per-entity key factories, never an inline key; outcomes declared in typed mutation `meta` and delivered by one global handler; queries are silent and render their own failure panel. **List state lives in the URL in the API's own query language** — `?sort=-email&filter[status]=active` — through the one codec in `@repo/contracts`; a record URL carries only the record, and the way back travels as history state through `shared/grid/record-navigation` (0044).
- **Resources** (0035): one `ResourceConfig` per resource — serializable config plus named registries — for both `AppGrid` (TanStack Table v9, manual mode, over shadcn `Table`) and config-driven RHF forms over the contracts zod schemas; every field disabled while a mutation is pending. Copy in a config is a translation key (0046).
- **The v2 grid** (0037–0042, 0044, 0045): a grid page is a height budget with one scroll container, a sticky header and a static pager, every wrapper down to `AppGrid` carrying `flex flex-col flex-1 min-h-0` and nothing on that path clipping; `grid` capability flags say what a surface _offers_, `can(action, resource)` says who may use it, conjoined once per screen so `shared/grid` never learns a resource name; bulk delete is a bounded client-side fan-out with per-item refusals; no filter row — a filterable column gets a header dialog that commits on Apply, `grid.hotFilters` are toolbar stances, and the applied-filters bar renders from the URL, never from the configs. **The URL owns view state, preferences own ergonomics, history state owns the way back, the table owns nothing durable.** Preferences, theme and locale are an account fact in `settings` with `localStorage` as the cache in front; the store never learns a `gridId` is on the wire.
- **Copy has two catalogues, both localized** (0046): error _codes_ in the `errors` i18n namespace (typed complete over `ErrorCode`), field _rules_ as zod's own messages through the client-side error map (`lv` map in `@repo/contracts/locales`); the API's `error.message` is never rendered. Every operator-facing string is a typed i18next key — a literal in JSX fails lint. `en` means en-GB; `lv` is machine-drafted pending native review.
- **Testing** (0036): Vitest + Testing Library + MSW with handlers derived from `@repo/contracts`; no live-API tier; a mock more permissive than the service certifies the opposite of production. Assertions by accessible name in English; the pseudo-locale suite proves no literal survived.
- **Invalidation**: a mutation invalidates its own entity's keys; the feature invalidates whatever else the interaction touched.
