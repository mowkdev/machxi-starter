# .claude — project configuration for Claude Code

- `settings.json` — shared permission defaults (safe pnpm/docker/git commands allowed; destructive DB/git ops ask; `.env` files never read). Personal overrides go in `settings.local.json` (git-ignored).
  - Recursive shell search (`grep -r`, `grep -R`, `find`, `rg`) is denied. Those commands ignore `.gitignore` and walk `node_modules` and `.turbo`, which is slow and floods the context. Use Claude's Grep/Glob tools instead — they are ripgrep-backed and skip anything `.gitignore`d.
- `agents/` — subagents: `adr-reviewer`, `module-builder`, `ui-builder`, `db-migrator`, `test-engineer`, `security-reviewer`, `adr-author`, and `gate-runner` (haiku, low effort, Bash-only: runs `pnpm check` or the full gate and returns a structured pass/fail — the cheap last stage of any workflow). The reviewers stay on the strongest model; the mechanical agents are the ones to tier down.
- `workflows/` — named multi-agent scripts for the Workflow tool (opt-in; a user asks for one by name or says "use a workflow"). `review-step` runs `adr-reviewer`, `security-reviewer` (when the scout finds the diff security-relevant) and `gate-runner` concurrently, then hands every finding to an independent refuter before reporting one ranked list — the orchestrated form of `/plan-step` step 5. Args: `range` (git diff range, default `HEAD`), `gate` (`check` | `full` | `none`), `security` (force on/off).
  - `run-deliverable` is the unattended form of `/plan-step` — the **building half**: a mechanical preflight (clean tree on `main`, Postgres up, every pending step parsed with its ADR list, done-when and any `proposed` ADR it is gated on — a plan it cannot execute mechanically is refused, not guessed at), then every pending step in order — build via the `plan-step` skill with the step's own text in the brief, `review-step` nested, up to `maxFixRounds` fix rounds, one commit per step **by explicit path** (never `git add -A`: another session may share the tree) — then the ADR-0025 rule 4 close, `git push origin main` (recorded `DENIED` rather than retried; never forced), and in `open-next`/`chain` mode the next deliverable — opened only when `plan-deliverable` reports it `ready`, otherwise the run stops with that deliverable's questions. It stops, never skips, on a red gate, a confirmed BLOCKER/MAJOR that survives the fix rounds, a gated step, or a blocked builder; browser-only checklist items are recorded as pending operator acceptance, never claimed. Args: `mode` (`ship` | `open-next` | `chain`), `maxDeliverables`, `maxFixRounds` (2), `push` (true). Invoke every workflow by `scriptPath` — the name registry has been seen stale for repo-authored scripts.
  - `plan-deliverable` is the **deciding half**, fronted by the `/plan-deliverable` skill because only the session can ask. `analyze` reads the scope document, the ADR index and the code in parallel and returns the operator's questions (2–4 options each, recommended first), the ADRs still needed and `ready`; `draft` (with the answers) writes each ADR `proposed` via `adr-author`, refutes it with `adr-reviewer` against the answers and the frozen ADRs, writes the build order with the plan left `planned`, runs a consistency check and commits by path; `open` flips the ledger mechanically and refuses if anything is still undecided. It never accepts an ADR — the first step's builder does, at its head.
  - Cost shape, measured on the D6→D7 chained run: the builders dominate (hundreds of turns each, a large context re-read per turn); reviewers, refuters and the gate are short. So the cheap tiers go on the many short agents (`gate-runner`, the scout, commit/push on haiku; MINOR refuters at low effort), the gate tier is the scout's ADR-0026 call (`full` only when `apps/api`, `packages/db` or `packages/contracts` moved), a small non-API diff gets one refuter lens, and the builder's brief carries the step text so it stops re-deriving it.
- `skills/` — slash-command workflows, split by where the code lives:
  - API and data: `/api-conventions`, `/new-api-module`, `/add-endpoint`, `/db-schema-change`, `/postman-sync`.
  - Admin app and design system (D3.10): `/frontend-conventions`, `/new-resource-ui`, `/ui-component`.
  - Everything else: `/new-adr`, `/local-dev`, `/plan-step`.

Root `CLAUDE.md` is the always-loaded summary; the ADRs in `docs/adr/` are the source of truth.
