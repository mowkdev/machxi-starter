# .claude — project configuration for Claude Code

- `settings.json` — shared permission defaults (safe pnpm/docker/git commands allowed; destructive DB/git ops ask; `.env` files never read). Personal overrides go in `settings.local.json` (git-ignored).
  - Recursive shell search (`grep -r`, `grep -R`, `find`, `rg`) is denied. Those commands ignore `.gitignore` and walk `node_modules` and `.turbo`, which is slow and floods the context. Use Claude's Grep/Glob tools instead — they are ripgrep-backed and skip anything `.gitignore`d.
- `agents/` — subagents: `adr-reviewer`, `module-builder`, `ui-builder`, `db-migrator`, `test-engineer`, `security-reviewer`, `adr-author`, and `gate-runner` (haiku, low effort, Bash-only: runs `pnpm check` or the full gate and returns a structured pass/fail — the cheap last stage of any workflow). The reviewers stay on the strongest model; the mechanical agents are the ones to tier down.
- `workflows/` — multi-agent scripts for the Workflow tool, **invoked by `scriptPath`** (the name registry has been seen stale for repo scripts). Two generations live side by side:
  - **v2 (current), written from scratch against Anthropic's agent guidance and the measured v1 run.** `step-review` — gate ∥ reviewers concurrently, only BLOCKER/MAJOR findings refuted (one lens, one shared agent configuration so the fan-out shares a cache prefix), MINORs reported not litigated, nothing refuted while the gate is red, and its own precision returned. `deliverable-plan` — `analyze` (scope + ADR index ∥ code facts → the operator's questions with a recommended answer each), `draft` (ADRs `proposed` via `adr-author`, each refuted by `adr-reviewer`, build order written, plan left `planned`, commit by path), `open` (mechanical, refuses anything undecided, never accepts an ADR). `deliverable-build` — runs **in a worktree on its own branch** (refuses `main` and the main checkout), every pending step in order with the step's own text in the builder's brief, `step-review`, bounded fix rounds, commits by explicit path, the ADR-0025 rule 4 close, then the branch pushed and a PR opened (`merge: "pr"`) or fast-forwarded to main (`merge: "main"`), and in chain mode the next deliverable only when `deliverable-verify` says ready. Cheap tiers on the mechanical agents (scout, gate, commit, ship on haiku). Fronted by `/plan-deliverable` (asks) and `/run-deliverable` (EnterWorktree, then launch). **The pipeline is three stages: decide by hand → verify → build.** `deliverable-verify` is stage 2 — read-only but for one line: each ADR refuted against the frozen ADRs, its siblings and the code (`Explore` scout + one `adr-reviewer` per ADR), the plan checked against the ADRs (every decision implemented, every pending step with ADRs that exist and a checkable done-when, nothing gated on an unaccepted `proposed` ADR, no open marker), and on a clean verdict a `- Verified for build: … at <hash>` line stamped into the plan and committed by path. `deliverable-build`'s preflight requires the stamp and refuses drift since its hash (any other ADR changed, or a pending step's ADR list / done-when changed; acceptance, labelled amendments of the deliverable's own ADRs and step notes are allowed); at a chain boundary it runs `deliverable-verify` on the next deliverable and opens it itself — it never drafts. `deliverable-plan` is therefore a stage-1 assistant (`analyze` opens the ADR-writing session with the questions), not a dependency.
  - **v1 (reference): `review-step`, `run-deliverable`, `plan-deliverable`.** The generation the D6→D7 chained run executed on — 46 agents, 370 agent-minutes, 406k output, 87M cache-read; builders 82% of the minutes; 27 reviewer/refuter agents with 26 of 27 refuter votes rejecting the reviewer's findings. Kept unchanged as the baseline v2 is compared against; do not launch them for new work.
- `rules/` — path-scoped rules (`paths:` frontmatter): `api.md` loads with `apps/api` and the data packages, `frontend.md` with `apps/admin` and `packages/ui`. They carry the ADR non-negotiables that used to make `CLAUDE.md` 13 KB; `CLAUDE.md` keeps what always applies.
- `.worktreeinclude` (repo root) — the untracked files copied into a worktree Claude creates: `.env`, `apps/admin/.env`.
- `skills/` — slash-command workflows, split by where the code lives:
  - API and data: `/api-conventions`, `/new-api-module`, `/add-endpoint`, `/db-schema-change`, `/postman-sync`.
  - Admin app and design system (D3.10): `/frontend-conventions`, `/new-resource-ui`, `/ui-component`.
  - Process — decide by hand → verify → build: `/new-adr`, `/plan-deliverable` (stage-1 assistant), `/verify-deliverable` (stage 2), `/run-deliverable` (stage 3, in a worktree), `/plan-step` (one step at the desk), `/local-dev`.

Root `CLAUDE.md` is the always-loaded summary; the ADRs in `docs/adr/` are the source of truth.
